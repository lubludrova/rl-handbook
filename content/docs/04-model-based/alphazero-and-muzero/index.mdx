> **Abstract.** We begin our study of model-based methods with tree search: using a model to explore possible consequences before choosing an action. This is a natural starting point for tasks with discrete actions, such as board games, where each move opens a set of possible continuations. Starting with known game rules lets us understand search before introducing model learning. We develop Monte Carlo tree search, then study AlphaZero, which learns policy and value predictions to guide search, and MuZero, which also learns the dynamics used inside the tree.

In the [Model-Based Framework](/docs/04-model-based/model-based-rl-framework), we introduced **decision-time planning**: using a model to compare possible futures before choosing the next action. We distinguished two common approaches within this family: **tree search** and **trajectory planning**. Tree search organizes possible continuations into a branching structure and allocates computation among them. In a board game, this means examining candidate moves, the opponent’s replies, and our subsequent responses. Trajectory planning instead searches for a sequence of actions over a chosen horizon, for example a sequence of steering and acceleration commands. Model predictive control (MPC) uses such a plan by executing its first action and planning again after observing the result. Discrete moves make tree search particularly easy to follow, while trajectory optimization is often convenient for continuous controls. We begin with tree search and known game rules so that we can understand how a model supports action selection before introducing model learning.

## Tree Search as Planning

Suppose a model can tell us what follows every available action. How should we use it to choose the next one? The most direct answer is to examine all possible continuations, compute their returns, and work backward to the current decision. Before making this procedure efficient, let us understand what it would compute if we could afford it.

<span id="a-small-tree-with-known-rules" />

We begin with a single agent in a deterministic, finite episodic task. A state $s$ has a finite set of legal actions $\mathcal A(s)$. The known transition function $f$ produces the next state, $s'=f(s,a)$, and the known reward function $r(s,a)$ gives the reward on that transition. The model can be queried at hypothetical states without changing the real environment.

For this first example, intermediate rewards are zero and the discount factor is $\gamma=1$. The only nonzero rewards can occur on transitions that end the episode. We record that final reward on the incoming transition and set the continuation value of a terminal state to zero. This way, every reward enters a return exactly once. Consider the following decision. From $s_0$, the agent can choose $L$ or $R$. Both transitions have reward zero. At the next state, it chooses $x$ or $y$ and receives a final reward.

The **root** represents the current state. An **edge** represents an action and its modeled transition. A **child** represents the resulting state. A terminal node marks the end of the task. More generally, a node identifies a particular continuation from the root. Two different action sequences can reach the same environment state while remaining separate nodes in a tree.

What should the agent do at $s_0$? We already know how to answer this with the Bellman equations. To compare an action with its alternatives, combine its immediate reward with the best continuation value:

$$
\begin{aligned}
Q^*(s,a)&=r(s,a)+V^*(f(s,a)),\\
V^*(s)&=\max_{a\in\mathcal A(s)}Q^*(s,a).
\end{aligned}
$$

The discount is absent because we set it to one. At a terminal state, $V^*=0$. At the two states immediately above the terminal nodes, the action values are therefore just the final rewards:

$$
\begin{aligned}
V^*(s_L)&=\max\{1,0\}=1,\\
V^*(s_R)&=\max\{-1,2\}=2.
\end{aligned}
$$

Now move one level backward. The first transitions have reward zero, so

$$
Q^*(s_0,L)=0+V^*(s_L)=1,
\qquad
Q^*(s_0,R)=0+V^*(s_R)=2.
$$

The best first action is $R$. This answer assumes that the agent also makes the best subsequent choice, $y$. Nothing has happened in the real environment during these calculations. The agent has queried its model, compared hypothetical continuations, and produced one action. Only now does it execute $R$. After observing the resulting state, it can plan again.

<span id="what-changes-with-stochastic-transitions" />

**What changes with stochastic transitions?** So far, we have assumed that taking an action in a given state always produces the same next state. In a stochastic environment, the same action can have several possible outcomes. For example, a command to move right may succeed or leave the agent in place if the surface is slippery. An action sequence therefore no longer determines a single path through the environment. To evaluate it, we must account for the possible outcomes and the decisions that follow each one, rather than examine just one continuation. Tree search remains possible, but handling this additional uncertainty makes planning more involved. A practical simplification is to ignore the transition noise and plan as though the dynamics were deterministic. When the noise is small and has little effect on which actions are preferable, this approximation can still produce useful decisions, although they may be suboptimal in the actual environment. We will use deterministic dynamics throughout the worked examples in this chapter so that we can develop the search mechanisms without also tracking random transition outcomes.

## A First Approximation: Monte Carlo Rollouts

<span id="why-not-expand-the-whole-tree" />

What if we are playing a more complex game, with far more than four possible continuations? Suppose the agent has $b$ actions to choose from at each step and we want to look ahead for $H$ steps. A full tree then has $b^H$ leaves. Even $b=10$ and $H=6$ give one million action sequences. Now imagine how many sequences we would need to examine to look ahead through an entire game of chess. We need to save computation in two ways: stop expanding at a manageable depth and estimate the remaining return, and spend more effort on some branches than on others. We begin by limiting the depth of explicit search and estimating what remains.

A simple method expands the tree to a chosen depth $d$. At each frontier state, it stops branching and runs a **rollout policy** $\pi_0$. This policy chooses actions until the episode ends. It could be uniformly random over legal actions or use a cheap heuristic. Let a rollout start at an unfinished state $s$. Write $G^{(i)}(s)$ for the sum of rewards in its $i$th sampled continuation. Under our undiscounted convention, this is the final payoff in the toy task. To reduce the variability of one sample, average $m$ rollouts:

$$
\widehat V^{\pi_0}_m(s)
=\frac{1}{m}\sum_{i=1}^{m}G^{(i)}(s).
$$

The data here comes entirely from model simulations. Increasing $m$ supplies more samples of what $\pi_0$ does in that model. It does not collect additional transitions from the real environment.

<span id="which-value-are-we-estimating" />

For example, stop expanding our tree at $s_L$ and $s_R$, and let $\pi_0$ choose $x$ and $y$ with equal probability. Suppose three rollouts from $s_L$ return $1,0,1$, while three from $s_R$ return $-1,2,2$. Averaging gives

$$
\widehat V^{\pi_0}_3(s_L)=\frac{1+0+1}{3}=\frac23,
\qquad
\widehat V^{\pi_0}_3(s_R)=\frac{-1+2+2}{3}=1.
$$

These samples favor $R$, but another sample could favor $L$. More rollouts reduce this sampling error, yet they still evaluate the same policy $\pi_0$. In fact, its expected return is $0.5$ from either state, whereas the optimal values are $1$ and $2$. Accurate rollout estimates therefore do not necessarily reveal the best continuation.

How do the rollout results help us choose an action at the root? Suppose the average returns from the four frontier states in the diagram give the following estimates, written as $\widehat V(s)$:

$$
\begin{aligned}
\widehat V(s_3)&=0.2, &\widehat V(s_4)&=0.8,\\
\widehat V(s_5)&=0.4, &\widehat V(s_6)&=0.6.
\end{aligned}
$$

These are illustrative rollout estimates for the larger tree. Keep the rewards on its explicit edges at zero and $\gamma=1$. We can now work backward, choosing the better action at each state:

1. At $s_1$, action $a_2$ leads to $s_3$, whose estimate is $0.2$, while $a_3$ leads to $s_4$, whose estimate is $0.8$. Choosing $a_3$ gives the backed-up estimate $\widehat V(s_1)=\max\{0.2,0.8\}=0.8$.
2. At $s_2$, we compare $0.4$ from $s_5$ with $0.6$ from $s_6$. Choosing $a_5$ gives $\widehat V(s_2)=\max\{0.4,0.6\}=0.6$.
3. At the root $s_0$, action $a_0$ leads to the branch estimated at $0.8$, while $a_1$ leads to the branch estimated at $0.6$. We therefore choose $a_0$ as the action to execute.

We **average sampled returns during rollouts** to estimate each frontier state's value, then **choose the best action in the explicit tree** to carry those estimates back to the root. This is how the two parts of the diagram work together.

So far, we have expanded every branch to the same depth and given every frontier the same number of rollouts. Some branches may already look unpromising, yet they receive as much computation as those that could determine the root action. Can the next simulation be allocated more intelligently?

## From Uniform Search to UCT

Which branch should receive the next simulation? Choosing the action with the highest current estimate can miss a better continuation. In our example, one rollout after $L$ may return $1$, while one after $R$ returns $-1$. A greedy search can then keep choosing $L$ without discovering the payoff $2$ available after $R$. This is the same exploration–exploitation problem we encountered in [multi-armed bandits](/docs/01-value-based/multi-armed-bandits#ucb-optimism-under-uncertainty). UCB balances the observed mean against an exploration bonus. **UCT**, or **UCB applied to Trees**, uses this idea at each decision node: outgoing actions play the role of arms, and simulated returns supply their samples.

<span id="keep-search-statistics-on-edges" />

For each tree edge $(s,a)$, let $N(s,a)$ count the simulations that traversed it. Store their accumulated return $W(s,a)$ and, once the count is positive, their mean:

$$
W(s,a)=\sum_{i=1}^{N(s,a)}G^{(i)}_{s,a},
\qquad
Q(s,a)=\frac{W(s,a)}{N(s,a)}.
$$

Here $G^{(i)}_{s,a}$ is the return from the beginning of that edge in its $i$th simulation. In our current example, it is the terminal payoff. These quantities are temporary statistics of the search tree, distinct from a learned $Q$-network.

<span id="value-plus-an-exploration-bonus" />

To select the next branch, define $N(s)$ as the total number of departures through the node's explicit outgoing edges. Once every available action has been tried, use

$$
\begin{aligned}
N(s)&=\sum_{b\in\mathcal A(s)}N(s,b),\\
U_{\mathrm{UCT}}(s,a)
&=c\sqrt{\frac{\log N(s)}{N(s,a)}},\\
a_{\mathrm{select}}
&=\arg\max_{a\in\mathcal A(s)}
\left[Q(s,a)+U_{\mathrm{UCT}}(s,a)\right].
\end{aligned}
$$

The mean favors actions with good simulated returns. The bonus favors less-visited actions: it shrinks as an action receives samples and grows if the node keeps being searched while that action is neglected. The coefficient $c\gt0$ controls this balance relative to the scale of returns. At initialization, set $N=W=0$ on each edge and **select an unvisited action before applying the formula**, breaking ties in a fixed order. An edge's first sample defines its mean.

UCT allocates computation inside the model. The real action is chosen after search finishes. Unlike a stationary bandit, an edge's return distribution can change as search changes the decisions below it, so the bandit analogy motivates the rule without directly supplying a confidence guarantee. [Kocsis and Szepesvári, UCT](https://doi.org/10.1007/11871842_29)

## Monte Carlo Tree Search

We can now remove the uniformly expanded prefix. Start with the current state as the only node, and let UCT determine which parts of the tree deserve to grow. Each simulation follows an existing path, adds a child node when needed, evaluates the frontier, and updates the visited path. This incremental procedure is **Monte Carlo tree search**, or MCTS. UCT is the selection rule used in the version we develop first.

### One Simulation, Four Operations

The four operations have different jobs:

1. **Selection.** Starting at the root, choose actions through the existing tree. Use the unvisited-action rule when applicable and UCT otherwise.
2. **Expansion.** If the selected action has no child node in the tree yet, use the model to obtain the next state and add a node for it. Our basic implementation adds at most one new node per simulation.
3. **Evaluation.** If the resulting state is unfinished, estimate its remaining return with a rollout under $\pi_0$. If it is terminal, its continuation value is zero. The reward for reaching it is already on the incoming edge.
4. **Backpropagation (backup).** Move backward through the selected edges, form their returns, and update their counts and means.

After expansion, the orange node has been added to the search tree, but we still need to estimate how good that position is. Starting there, we use the model to play out the rest of the episode under the rollout policy $\pi_0$. We use the resulting return to evaluate the orange node, without adding the later rollout positions to the tree or recording separate visit counts for their actions. We then work backward from the orange node to the root, updating the statistics of the tree edges along that path. Thus, one simulation can play many additional moves while adding only one node to the stored search tree.

<span id="what-is-backed-up" />
<span id="nine-simulations-on-the-same-tree" />

### Updating the Tree

The evaluation step is complete. How do we use its result to update the tree? Let $G$ be the total reward obtained in this simulation. With zero intermediate rewards and $\gamma=1$, this is just the final reward, and it is the same return from every edge traversed in the explicit tree. Each of those edges receives $G$ as one new sample. For an edge $(s,a)$, update its statistics as follows:

$$
\begin{aligned}
N_{\mathrm{new}}(s,a)&=N(s,a)+1,\\
W_{\mathrm{new}}(s,a)&=W(s,a)+G,\\
Q_{\mathrm{new}}(s,a)&=\frac{W_{\mathrm{new}}(s,a)}{N_{\mathrm{new}}(s,a)}.
\end{aligned}
$$

The subscript “new” denotes the statistics after this update. We add one visit, add the current simulation's return to the accumulated total, and recompute the mean. On an edge's first visit, its count becomes one and its mean is simply $G$. Later simulations refine that mean by contributing additional returns.

The updated means and counts change the UCT scores, so the next simulation can follow a different path and expand another part of the tree. This feedback makes the tree grow selectively. Unlike the earlier fixed-depth search, this version of MCTS accumulates mean simulated returns, while UCT controls which continuations contribute to those means.

<span id="choosing-the-real-action" />

### From Search to Action

Once the simulation budget is exhausted, the agent must choose an action to execute in the environment. A natural choice is to compare the expected total returns estimated during search and select the action with the highest estimate. This is the rule used in the original UCT algorithm. At the current root $s_0$, we choose among the actions explored during search:

$$
\begin{aligned}
a_{\mathrm{real}}
&=\arg\max_{a:\,N(s_0,a)\gt0}Q(s_0,a),\\
Q(s_0,a)&=\frac{W(s_0,a)}{N(s_0,a)}.
\end{aligned}
$$

However, $Q$ is only an estimate based on a finite number of simulations. An action explored just a few times may have a high average because its sampled continuations happened to be favorable. Some MCTS systems instead choose the most-visited action at the root, using the search's allocation of simulations to determine the final move. AlphaZero, for example, uses this rule when evaluating its agent. Here $N(s_0,a)$ counts how many times action $a$ was selected at the root during search:

$$
a_{\mathrm{real}}
=\arg\max_{a\in\mathcal A(s_0)}N(s_0,a).
$$

<span id="two-player-games-and-minimax" />

<span id="keep-the-exploration-bonus-positive" />

### Searching against an Opponent

Can we use the same search procedure to play chess? The rules tell us exactly what follows any legal move, but they do not tell us which reply the opponent will choose. Instead of modeling a particular opponent's reasoning, we search over both players' moves, treating each player as trying to maximize their own return. In a zero-sum game, this means minimizing the other player's return: a move must be judged against the opponent's strongest reply. This is the idea behind **minimax**. We can apply MCTS at both players' decision nodes, with each side seeking a favorable outcome.

We use a second agent to choose the opponent's moves. The first agent maximizes the game outcome $Z_1$ ($+1$ for a win, $0$ for a draw, $-1$ for a loss), while the second minimizes it. The sign $o(s)$ converts this result to the perspective of the player whose turn it is:

$$
\begin{aligned}
o(s)&=
\begin{cases}
+1,&\text{first player's turn},\\
-1,&\text{second player's turn},
\end{cases}\\
G(s,a)&=o(s)Z_1.
\end{aligned}
$$

Under our assumptions of zero intermediate rewards and no discounting, $G(s,a)$ is the sample added to edge $(s,a)$. Its mean $Q(s,a)$ therefore measures the outcome **for the player choosing that action**. Both players can maximize their own $Q$: an action that looks good for the opponent can look bad for us. During search, each player also receives a positive exploration bonus:

$$
a_{\mathrm{select}}
=\arg\max_a
\left[
Q(s,a)+c\sqrt{\frac{\log N(s)}{N(s,a)}}
\right].
$$

As before, unvisited actions are selected before applying this formula. Only the value term reflects the players' opposing objectives. The exploration bonus stays positive because either player may benefit from investigating a less-visited action. After search, the value-based final-action rule also uses the acting player's perspective:

$$
a_{\mathrm{real}}
=\arg\max_{a:\,N(s_0,a)\gt0}Q(s_0,a).
$$

With this player-relative return, the rest of MCTS works as before. The whole algorithm works without a single neural network, which feels almost suspicious in a modern RL chapter. Let's fix that. Following our experience in the model-free chapters, we can represent the policy and value functions with neural networks. AlphaZero combines both in one network and trains it using search results and outcomes from self-play.

## AlphaZero: Neural Search and Self-Play

Search compares moves at one position. How can we preserve that work for other positions? AlphaZero learns a policy that imitates search preferences and a value function that predicts game outcomes. We first use these predictions inside MCTS, then explain how to train them.

<span id="policy-and-value-predictions" />

### MCTS with Neural Guidance

One network with parameters $\theta$ has two output heads:

$$
\big(p_\theta(s),V_\theta(s)\big)=f_\theta(s).
$$

The policy $p_\theta(a\mid s)$ predicts move probabilities. The value $V_\theta(s)$ predicts the expected outcome for the player to move. Known rules still supply legal moves, transitions, and terminal outcomes.

<span id="replace-the-rollout-with-a-value-prediction" />

At an unfinished leaf $s_{\mathrm{leaf}}$, evaluate $V_\theta(s_{\mathrm{leaf}})$ instead of playing a rollout. Convert this estimate to each acting player's perspective when updating $N,W,Q$. For example, a leaf estimate $+0.6$ becomes $-0.6$ for the opposing player. At a terminal leaf, use the known outcome once, on its incoming transition, with zero continuation afterward.

<span id="a-policy-prior-for-selecting-branches" />
<span id="guiding-search-with-puct" />

For selection, normalize the policy over legal moves and store it as the prior $P(s,a)$. A simplified **PUCT** rule is

$$
\begin{aligned}
U_{\mathrm{PUCT}}(s,a)
&=c_{\mathrm{puct}}P(s,a)
\frac{\sqrt{N(s)}}{1+N(s,a)},\\
a_{\mathrm{select}}
&=\arg\max_{a\in\mathcal A(s)}
\Big[Q(s,a)\\
&\qquad\qquad+U_{\mathrm{PUCT}}(s,a)\Big].
\end{aligned}
$$

Here $N(s)=\sum_bN(s,b)$ and $c_{\mathrm{puct}}\gt0$. A larger prior encourages investigation, while visits reduce that action's bonus. Unlike UCT, unvisited actions have finite scores. In our teaching version, initialize their $Q$ to zero and choose a highest-prior action when $N(s)=0$. The network stays fixed during search, while counts and means change.

<span id="from-a-prior-to-a-search-distribution" />

After at least one root action has been visited, turn the counts into a search policy using a temperature $\tau\gt0$:

$$
\pi_{\mathrm{search}}(a\mid s)
=\frac{N(s,a)^{1/\tau}}
{\sum_{b\in\mathcal A(s)}N(s,b)^{1/\tau}}.
$$

At $\tau=1$, counts $30$ and $10$ give probabilities $0.75$ and $0.25$. Lower temperatures favor the most-visited move. Self-play samples moves and adds noise to the root prior for exploration. Evaluation chooses maximum visits. The network prior $p_\theta$, search mean $Q$, and visit distribution $\pi_{\mathrm{search}}$ have different roles.

### Learning through Self-Play

Start with a randomly initialized network and let MCTS choose moves for both players. At position $s_t$, search produces $\pi_t=\pi_{\mathrm{search}}(\cdot\mid s_t)$. Execute $a_t\sim\pi_t$, observe $s_{t+1}=f(s_t,a_t)$, and search again. These played moves form one game. The branches examined inside each search remain hypothetical. The chosen child's subtree can be retained for the next move.

When the game ends, assign each recorded position its outcome $Z=o(s_t)Z_1$. Store triples $(s_t,\pi_t,Z)$ in replay buffer $\mathcal D$. The policy target is available after search, while the outcome arrives after the game. Minibatches reuse positions from recent games to fit both heads:

$$
L(\theta)=\mathbb E_{(s,\pi,Z)\sim\mathcal D}\Big[\big(V_\theta(s)-Z\big)^2-\sum_{a\in\mathcal A(s)}\pi(a)\log p_\theta(a\mid s)\Big]+\lambda_{\mathrm{reg}}\|\theta\|_2^2.
$$

The squared error fits the value prediction to the observed outcome. Cross-entropy teaches the policy the full search distribution, rather than only the played move. The coefficient $\lambda_{\mathrm{reg}}\ge0$ controls weight regularization. Targets stay fixed during each update, and gradients pass through the shared network, without differentiating through MCTS.

<span id="alphago-alphago-zero-and-alphazero" />

Updated predictions guide later searches, whose results supply new training data. This is approximate [policy iteration](/docs/01-value-based/dynamic-programming): search investigates improvements and the network generalizes them. Finite search does not guarantee a better move every time. The same procedure was trained separately for chess, shogi, and Go.

## MuZero: Searching with a Learned Model

What if we can interact with the environment but cannot ask it to simulate hypothetical moves? AlphaZero needs the simulator to reach a leaf before evaluating it. In a deterministic task, the current situation and an action sequence determine that leaf. Could a network predict its reward, policy, and value without reconstructing the intervening observations? MuZero learns these predictions directly.

<span id="predict-the-quantities-search-uses" />

### Representation, Dynamics, and Prediction

MuZero encodes the available observation/action history $\mathcal H_t$ at real time $t$, then advances a latent state along candidate actions:

$$
\begin{aligned}
z_t^0&=h_\theta(\mathcal H_t),\\
(\widehat r_t^{k+1},z_t^{k+1})
&=g_\theta(z_t^k,a^k),\\
(\widehat p_t^k,\widehat V_t^k)
&=f_\theta(z_t^k).
\end{aligned}
$$

The **representation** $h_\theta$ encodes the history into an internal vector used as the search root. The **dynamics** $g_\theta$ predicts a reward and successor latent after hypothetical action $a^k$. The **prediction** $f_\theta$ supplies policy and value. Superscript $k$ counts depth from time $t$. Lowercase $z$ is a latent state, distinct from outcome target $Z$. These functions are trained jointly. Their objective requires no observation reconstruction.

<span id="expanding-a-latent-search-tree" />
<span id="restore-rewards-and-discounting-in-backup" />
<span id="searching-in-latent-states" />

To expand a selected edge, call $g_\theta$, then $f_\theta$ at the child. Another action from the same latent creates another branch. In a single-agent task such as Atari, predicted intermediate rewards and discounting enter backup as

$$
G_{\mathrm{parent}}=\widehat r+\gamma G_{\mathrm{child}}.
$$

For example, $\widehat r=1$, $\gamma=0.9$, and $G_{\mathrm{child}}=2$ give $2.8$. Alternating zero-sum games instead require player-relative signs. Counts and means are updated as before. Original MuZero also normalizes search values and adjusts PUCT's exploration coefficient with visits.

<span id="what-happens-after-a-real-action" />

Execute the selected action in the environment, observe its actual reward and next observation, and encode the updated history for the next search. Board games supply legal moves at the root. Internal latent nodes use learned predictions, including terminal behavior, rather than exact legality or termination tests.

<span id="training-muzero-from-real-trajectories" />
<span id="search-branches-training-follows-recorded-actions" />
<span id="unrolling-recorded-actions" />

### Learning from Real Trajectories

Store trajectories containing observations $o_t$, executed actions $a_t$, actual rewards $r_{t+1}$, and search policies $\pi_t$. Sample a starting history and $K$ subsequent transitions. Encode that history once, then apply the same recurrence with $a^k=a_{t+k}$ for $k=0,\ldots,K-1$. **Search branches over alternatives. Training follows the recorded actions.** No new observation is supplied inside this unroll.

<span id="constructing-a-value-target" />

For a simple single-agent value target, use the full episode return:

$$
Z_j=\sum_{i=j}^{T-1}\gamma^{i-j}r_{i+1},
$$

where $T$ is termination time. Board games use player-relative outcomes instead. Original MuZero bootstraps $n$-step targets in Atari, as in [multi-step TD](/docs/01-value-based/monte-carlo-and-temporal-difference).

<span id="fitting-reward-value-and-policy-together" />

At depth $k$, align the predictions with real time $t+k$:

| Prediction | Target |
|---|---|
| $\widehat p_t^k$ | Recorded search policy $\pi_{t+k}$ |
| $\widehat V_t^k$ | Return or outcome $Z_{t+k}$ |
| $\widehat r_t^k$, $k\ge1$ | Observed reward $r_{t+k}$ |

For a segment with $t+K\lt T$, every policy target exists. Combine policy, value, and reward losses across the sequence:

$$
L_t(\theta)=\sum_{k=0}^{K}\ell_p(\widehat p_t^k,\pi_{t+k})+\sum_{k=0}^{K}\ell_v(\widehat V_t^k,Z_{t+k})+\sum_{k=1}^{K}\ell_r(\widehat r_t^k,r_{t+k})+\lambda_{\mathrm{reg}}\|\theta\|_2^2.
$$

<span id="how-the-dynamics-learns-without-an-image-target" />

Here $\ell_p$ is cross-entropy. Squared errors for $\ell_v,\ell_r$ give a scalar teaching version. Original Atari MuZero uses transformed categorical targets, and board games without intermediate rewards omit reward loss.

Policy/value supervision starts at depth zero, reward supervision after the first action. At episode boundaries, mask unavailable policy targets and set terminal continuation targets to zero, or use explicit absorbing-state targets. Errors propagate through $f_\theta$, recurrent $g_\theta$, and root encoder $h_\theta$, with search policies held fixed.

<span id="what-search-gives-usand-what-it-costs" />

## Comparing MCTS, AlphaZero, and MuZero

| Component | Rollout-based MCTS | AlphaZero | MuZero |
|---|---|---|---|
| Successors | Supplied simulator | Known game rules | Learned latent dynamics |
| Unfinished leaf | Rollout return | Value head | Value head |
| Selection | UCT | Policy-guided PUCT | Policy-guided PUCT |
| Persistent learning | None required | Policy and value | Representation, dynamics, reward, policy, value |
| Training data | None required | Self-play search and outcomes | Executed trajectories and search targets |
| Work during search | Simulator calls and rollouts | Rules and network evaluations | Learned dynamics and prediction calls |
| Main prediction risk | Weak rollout continuation | Inaccurate leaf values | Reward, latent-dynamics, and value errors |

<span id="read-results-with-their-budgets" />
<span id="what-this-model-learnsand-what-search-cannot-repair" />
<span id="model-error-and-the-search-budget" />

AlphaZero and MuZero both use MCTS, but change how it evaluates and explores the tree. In the rollout-based version, a weak continuation policy can make a promising state look bad. AlphaZero keeps exact game rules and uses a learned policy to guide exploration and a value head to evaluate unfinished positions, so inaccurate predictions can still mislead the search. MuZero also predicts rewards and successor latent states: it can search without a supplied transition simulator, but model errors can accumulate along imagined branches. Tree statistics summarize the current search, while trained networks reuse information across positions. More simulations can refine estimates within the model, but cost time and memory and provide no new evidence about whether the model is correct.
