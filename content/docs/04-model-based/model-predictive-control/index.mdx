This chapter follows the **model for control** branch of the [Model-Based Framework](/docs/04-model-based/model-based-rl-framework): use predicted consequences to compute behavior. We start with known-model optimal control, then introduce decision-time replanning and finally learn the dynamics in PETS. This tradition developed alongside the [Dyna approach](/docs/04-model-based/dyna-and-learned-models), which uses model predictions to train reusable values or policies.

We initially assume a measured Markov state, continuous actions, and a specified cost function. LQR further assumes linear dynamics and quadratic costs. iLQR/DDP require useful local derivatives. Sampling optimizers require enough candidate evaluations. Any of these can fail if the model is inaccurate where optimization takes it. Replanning provides feedback, but does not make a wrong model correct or automatically ensure stability or constraint satisfaction.

**Environments.** Stabilizing a cart or a robot near a target illustrates LQR. Swinging up a pendulum and reaching with a nonlinear arm illustrate trajectory optimization. Learned dynamics become useful when the physical equations or their parameters are inadequate. PETS studies tasks including cart-pole, reaching, pushing, and HalfCheetah locomotion. A camera-only agent must additionally infer a state, which we address in [latent model-based RL](/docs/04-model-based/latent-model-based-rl).

> **Abstract.** An environment model, an optimizer, and a feedback controller are different components. LQR shows how dynamic programming can produce a feedback law directly. iLQR and DDP extend that idea locally to nonlinear trajectories. Random shooting and CEM optimize candidate sequences by sampling. MPC repeatedly solves a finite-horizon problem from the latest state. PETS combines this control scheme with learned probabilistic dynamics and trajectory sampling.

**Prerequisites:** [dynamic programming](/docs/01-value-based/dynamic-programming), the [model-based framework](/docs/04-model-based/model-based-rl-framework), and basic matrix algebra for the LQR derivation. The scalar example gives the same mechanism without matrices.

## Four Questions Hidden Inside “Use a Model”

Suppose a controller should move a cart toward a target. Knowing how a force changes its velocity does not yet specify what the controller should do. We must separate four decisions:

| Component | Question | Examples |
|---|---|---|
| Environment model | What happens after an action? | Known equations, learned neural dynamics |
| Objective | Which consequences are preferable? | Tracking error, effort, terminal cost, constraints |
| Solver | How do we find a good action or plan? | Riccati recursion, iLQR/DDP, random shooting, CEM |
| Control scheme | How does new information change actions? | Execute a sequence, evaluate feedback gains, repeatedly replan |

If the model is learned, a fifth component fits its parameters from experience. Changing that learning algorithm does not automatically change the solver or the way feedback is used.

The distinction matters immediately. **Open-loop control** executes a precomputed sequence without adjusting it to new measurements. **Closed-loop control** uses measurements to alter actions. A fixed state-feedback law is closed-loop even if it never solves an optimization problem online. **MPC is one particular way to implement feedback**, by repeatedly solving a finite-horizon planning problem.

## LQR: Dynamic Programming Can Produce a Feedback Law

The linear-quadratic regulator (**LQR**) is a classical optimal-control problem with an unusually tractable structure. For a finite horizon, consider

$$
x_{j+1}=Ax_j+Bu_j,
$$

and minimize

$$
C=\sum_{j=0}^{H-1}
\left(x_j^\top Q_x x_j+u_j^\top R_u u_j\right)
+x_H^\top Q_f x_H.
$$

Here $x_j$ is the state, $u_j$ the control, and $A,B$ are known dynamics matrices. We use the control literature's $x,u$ in this derivation. They play the same roles as RL's $s,a$. The matrices $Q_x,Q_f$ are positive semidefinite, and $R_u$ is positive definite. They penalize state error and control effort. $Q_x$ is a cost matrix, not an action-value function. There are no hard state or action constraints in this basic problem.

The target is the origin. Tracking another equilibrium can often be written in error coordinates. Define $V_j(x)$ as the minimum remaining **cost**, so Bellman's recursion uses a minimum:

$$
V_j(x)=\min_u\left[
 x^\top Q_x x+u^\top R_u u
 +V_{j+1}(Ax+Bu)
\right],
\qquad V_H(x)=x^\top Q_f x.
$$

Quadratic costs and linear transitions preserve a quadratic value function. If $V_{j+1}(x)=x^\top P_{j+1}x$, collect the terms involving $u$ and differentiate:

$$
2(R_u+B^\top P_{j+1}B)u
+2B^\top P_{j+1}Ax=0.
$$

Thus the minimizing control is

$$
\begin{aligned}
u_j^*(x)&=-K_jx,\\
K_j&=(R_u+B^\top P_{j+1}B)^{-1}B^\top P_{j+1}A.
\end{aligned}
$$

Substitution into the Bellman equation gives the backward Riccati recursion:

$$
\begin{aligned}
P_H&=Q_f,\\
P_j&=Q_x+A^\top P_{j+1}A
-A^\top P_{j+1}BK_j.
\end{aligned}
$$

This is dynamic programming without enumerating a grid of continuous states. The matrices represent the whole quadratic value function. Compute the gains backward once, then apply the appropriate gain to the measured state at each time step. Under suitable stabilizability and detectability conditions, the infinite-horizon time-invariant problem has a stabilizing stationary solution. Those conditions matter. A finite-horizon quadratic objective alone is not a blanket stability guarantee. [MIT Underactuated Robotics, LQR](https://underactuated.mit.edu/lqr.html)

### A Scalar Calculation

Let $x'=x+u$ and consider one step with cost

$$
x^2+u^2+(x+u)^2.
$$

Its derivative with respect to $u$ is $4u+2x$, so $u^*(x)=-x/2$. At $x=2$, choose $u=-1$. If the measured state at that decision is instead $3$, the same law chooses $-1.5$. The gain was already computed. Feedback changes the action without an online search.

By contrast, storing the number $-1$ and applying it regardless of the measured state is open-loop. Both actions came from the same dynamics and objective, but they use observations differently. A trained RL actor $a=\pi(s)$ likewise implements feedback when its input is the current state. Closed-loop control is not exclusive to model-based methods.

The limitation is structural. A large pendulum swing, contacts during locomotion, or an obstacle usually does not fit one global linear model with a quadratic cost. The next step is to exploit LQR-like structure locally.

## Nonlinear Dynamics: iLQR and Differential Dynamic Programming

For a nonlinear system $x_{j+1}=f(x_j,u_j)$, begin with a nominal action sequence $\bar u_{0:H-1}$ and simulate its states $\bar x_{0:H}$. The aim is to improve this trajectory, not solve the problem globally over every possible state.

**Differential dynamic programming (DDP)** is the older local dynamic-programming approach. **Iterative LQR (iLQR)** uses closely related backward and forward passes with a simpler dynamics approximation. The 2004 iLQR formulation makes the link to repeated linearization explicit. [Li and Todorov, 2004](https://roboti.us/lab/papers/LiICINCO04.pdf)

Around the nominal trajectory, linearize the dynamics:

$$
\delta x_{j+1}\approx A_j\delta x_j+B_j\delta u_j,
\qquad
A_j=\left.\frac{\partial f}{\partial x}\right|_{\bar x_j,\bar u_j},
\quad
B_j=\left.\frac{\partial f}{\partial u}\right|_{\bar x_j,\bar u_j}.
$$

Approximate the running cost and remaining value quadratically. Unlike the centered LQR problem, their expansions generally contain linear terms because the nominal trajectory is not optimal.

To see what a backward pass computes, write the local cost-to-go as $\mathcal Q_j(x,u)=\ell(x,u)+V_{j+1}(f(x,u))$. Its quadratic expansion contains terms

$$
\mathcal Q_u^\top\delta u
+\frac12\delta u^\top\mathcal Q_{uu}\delta u
+\delta u^\top\mathcal Q_{ux}\delta x.
$$

The derivatives are evaluated along the nominal trajectory. If $\mathcal Q_{uu}$ is positive definite, minimizing this expression gives

$$
\begin{aligned}
\delta u_j&=k_j+K_j\delta x_j,\\
k_j&=-\mathcal Q_{uu}^{-1}\mathcal Q_u,\\
K_j&=-\mathcal Q_{uu}^{-1}\mathcal Q_{ux}.
\end{aligned}
$$

The vector $k_j$ improves the nominal action. The matrix $K_j$ corrects deviations from the nominal state. Here the minus sign is included in $K_j$, unlike the preceding LQR convention $u=-Kx$.

A practical iteration has three parts:

1. **Backward pass:** propagate local value derivatives from the terminal cost and compute $k_j,K_j$.
2. **Forward pass:** roll out the nonlinear model using $u_j=\bar u_j+\alpha k_j+K_j(x_j-\bar x_j)$, trying a step size $\alpha$ that improves the actual modeled trajectory cost.
3. **Repeat:** use the accepted trajectory as the next nominal trajectory, recompute derivatives, and stop at a convergence or computation limit.

Regularization makes the local control Hessian suitable for solving the backward step. Line search checks whether a proposed local improvement survives the nonlinear rollout. In implementations, solve linear systems rather than explicitly forming the inverses displayed above.

### What Distinguishes iLQR from DDP?

In the usual distinction, iLQR retains first derivatives of dynamics in the local backward model, whereas full DDP also retains second derivatives of dynamics. For example,

$$
\begin{aligned}
\mathcal Q_{uu}^{\mathrm{iLQR}}
&=\ell_{uu}+B_j^\top V_{xx}'B_j,\\
\mathcal Q_{uu}^{\mathrm{DDP}}
&=\ell_{uu}+B_j^\top V_{xx}'B_j
+\sum_i V_{x_i}'\,\frac{\partial^2 f_i}{\partial u\partial u^\top}.
\end{aligned}
$$

The prime marks derivatives of the next-step value, and $f_i$ is one coordinate of the dynamics. Both methods retain quadratic cost information. Omitting dynamics Hessians does not turn iLQR into first-order gradient descent. The approximation trades curvature information for cheaper derivative computation. [Tassa, Mansard, and Todorov, 2014](https://roboti.us/lab/papers/TassaICRA14.pdf)

Both are local methods: initialization, nonsmooth contacts, and poor derivatives can determine which solution is found. Hard action bounds require a constrained variant. Clipping an unconstrained solution need not solve the constrained optimization problem.

Their output can include local feedback gains, so one can track a computed trajectory without resolving the full optimization at each measurement. Alternatively, one can rerun the optimizer as the state changes. That latter control arrangement leads toward MPC. It is a separate choice from using iLQR or DDP as the solver.

## Sampling Optimizers: Random Shooting

A different optimization tradition avoids derivatives. It is useful when the model can simulate a sequence but its local derivatives are unavailable, unreliable, or inconvenient. Sampling is an alternative to local quadratic optimization, not the next historical version of iLQR.

For a fixed current state and horizon $H$, random shooting:

1. Draws $N$ candidate action sequences $u_{0:H-1}^{(i)}$ from a specified distribution.
2. Rolls each sequence through the model and evaluates its cost or return.
3. Returns the best sampled sequence.

What happens to that sequence is a control decision: execute it open-loop, track it with another controller, or execute only its first action and replan. Random shooting by itself specifies none of these feedback arrangements.

The advantage is a simple, batchable optimization procedure with no need to differentiate the transition or reward function. The limitation is coverage. With action dimension $d_a$, the search space has dimension $Hd_a$. A long sequence can contain many poor choices even if some of its individual actions are promising.

A deterministic model requires roughly $NH$ transition predictions. With $P$ stochastic particles per candidate, the cost grows to roughly $NHP$. These are model computations. The environment does not execute every candidate.

## The Cross-Entropy Method

The cross-entropy method, or CEM, adapts the sampling distribution toward good candidates. A simple continuous-action version uses a diagonal Gaussian over action sequences:

$$
u^{(i)}\sim
\mathcal N(\mu,\operatorname{diag}(\sigma^2)).
$$

For each CEM iteration, evaluate $N$ candidates and retain an elite set $\mathcal E$ of the $K$ highest-return sequences. Refit:

$$
\begin{aligned}
\mu_{\mathrm{elite}}&=
\frac1K\sum_{i\in\mathcal E}u^{(i)},\\
\sigma^2_{\mathrm{elite}}&=
\frac1K\sum_{i\in\mathcal E}
(u^{(i)}-\mu_{\mathrm{elite}})^2.
\end{aligned}
$$

The square is coordinatewise. These are statistics of **actions at each sequence position**, not of predicted states or trajectory rewards.

Often the update is smoothed:

$$
\mu\leftarrow\eta\mu+(1-\eta)\mu_{\mathrm{elite}},
\qquad
\sigma^2\leftarrow\eta\sigma^2+
(1-\eta)\sigma^2_{\mathrm{elite}},
$$

with $0\le\eta\lt1$. A variance floor or stopping condition can prevent unproductive numerical collapse. The pinned PETS implementation uses bounded sampling and smoothed elite refits. This diagonal-Gaussian description captures the core procedure, not every implementation detail. [PETS CEM implementation](https://github.com/kchua/handful-of-trials/blob/77fd8802cc30b7683f0227c90527b5414c0df34c/dmbrl/misc/optimizers/cem.py)

If two elite two-step sequences are $(0.8,0.4)$ and $(1.0,0.6)$, the fitted mean is $(0.9,0.5)$ and each coordinate's maximum-likelihood variance is $0.01$. If bounds apply, sampling must respect them. Simply clipping an unconstrained Gaussian changes its distribution and can pile probability at the boundary.

CEM is an optimizer, not an uncertainty estimator. A narrow action distribution means its search has concentrated, not that the dynamics prediction is reliable.

Stop after a chosen iteration budget or when the proposal variance is sufficiently small. The pinned PETS optimizer returns the final smoothed mean sequence. This convention differs from random shooting's best sampled candidate and need not return a sequence that was itself evaluated. A concentrated proposal can also miss a better region: finite-budget CEM has no general global-optimality guarantee.

## MPC: Turn Repeated Optimization into Feedback

Imagine steering a cart toward a target. An open-loop controller chooses ten forces and executes all ten without checking where the cart went. If the first push is stronger than expected, every later force is based on a position the cart never reached.

Model predictive control, or MPC, also evaluates sequences of forces. It executes only the beginning, usually one action, observes the resulting state, and solves a new planning problem from there. The planning horizon moves forward with the controller.

At time $t$, let $u_{0:H-1}$ denote a candidate sequence of $H$ actions. A general discounted planning objective is

$$
J_H(s_t,u_{0:H-1})=
\mathbb E_{\hat p}\left[
\sum_{j=0}^{H-1}\gamma^j\hat r(s_j,u_j)
+\gamma^H\hat V(s_H)
\;\middle|\;s_0=s_t
\right].
$$

The index $j$ is relative to the current planning call. Each action produces one reward and one next state. The terminal value estimates the return beyond the final modeled state. It must not count an immediate reward already included in the sum.

For episodic tasks, rewards after termination are zero and the terminal value is zero on terminated trajectories. The expression above suppresses those masks for readability. Implementations must handle them.

Solve approximately for a good sequence $u^*$ and execute $a_t=u_0^*$. Then observe the real $s_{t+1}$ and repeat. The unexecuted actions are a proposal for future behavior, not a commitment.

This general objective has several variants. A classical controller may use known dynamics and an engineered terminal cost. Original PETS uses learned dynamics and the known task reward/cost, with **no learned terminal critic**. We set $\hat V=0$ for the PETS walkthrough. A learned terminal value will become central in [TD-MPC](/docs/04-model-based/latent-model-based-rl). [Chua et al., PETS](https://arxiv.org/abs/1805.12114)

## A Small Planning Calculation

Consider the deterministic system

$$
x_{j+1}=x_j+u_j,
\qquad u_j\in[-1,1].
$$

Start at $x_0=0$, aim for $x=2$, and minimize the two-step cost

$$
C(u_0,u_1)=
(x_1-2)^2+0.1u_0^2+
(x_2-2)^2+0.1u_1^2.
$$

For the candidate $(1,1)$, states are $1,2$ and cost is $1.2$. For $(0,1)$, states are $0,1$ and cost is $5.1$. The first candidate looks better, so execute its first action, $1$.

Now suppose the observed next state is $0.7$ because the cart slipped. MPC starts the next optimization at $0.7$, not at the predicted $1$. It can revise the next force.

This illustrates feedback, not a guarantee that the revised action succeeds. If the model systematically misunderstands slipping, each new plan can still be wrong. Feedback corrects the starting state. Learning and robust control address other errors.

### An Open-Loop Plan Can Be Inside a Closed-Loop Controller

In the simple MPC formulation above, the optimizer chooses one sequence. Under uncertain dynamics, its future actions do not depend on which predicted state occurs: every particle receives the same action at sequence position $j$. The optimization therefore searches open-loop candidates. The **executed controller** is nevertheless closed-loop because it observes a new real state and solves a new problem before the next action.

This is less general than optimizing a full policy tree whose future actions depend on future observations. Stochastic and robust MPC can use richer policy parameterizations. The distinction prevents a common mistake: replanning does not mean the internal finite-horizon optimization has accounted for every future feedback response.

After executing one action, a controller can shift the remaining mean sequence forward and append a default final action. This **warm start** reuses the previous plan. It should still allow enough variation to respond to a new observation.

MPC need not start optimization from scratch. It can reuse the shifted plan or local feedback solution. Nor must it use CEM: iLQR, DDP, or other constrained solvers can solve its inner problem. Conversely, a fixed LQR gain or a precomputed iLQR tracking law can use feedback without receding-horizon optimization. MPC also predates learned neural dynamics. Fitting a model is an additional learning loop, not part of its definition.

## PETS: Add Learned Dynamics and Propagate Uncertainty

When dynamics are unknown, collecting transitions and fitting a neural predictor makes the MPC scheme adaptive to experience. A deterministic point predictor is a starting point, but recursive predictions can hide multiple possible futures and limited-data uncertainty. PETS (2018), or **Probabilistic Ensembles with Trajectory Sampling**, addresses this modeling problem while retaining decision-time MPC. It combines probabilistic neural dynamics, an ensemble representing alternative fitted models, and particles for evaluating candidate sequences.

Each member predicts a next-state distribution, often a Gaussian over state differences. Training uses transition likelihoods on collected data. Planning starts multiple particles at the current observed state, advances them under a candidate action sequence, and averages their returns. [PETS, Sections 4–5](https://arxiv.org/abs/1805.12114)

Within-member variability models outcome uncertainty. Disagreement between members is a proxy for uncertainty about the fitted dynamics. These are often called aleatoric and epistemic uncertainty. The separation is approximate: all members can share the same blind spot, and apparent noise can reflect missing state. An ensemble is not automatically a calibrated posterior or an error certificate.

For candidate $i$, let $s_j^{(i,p)}$ be particle $p$ at simulated step $j$. Original PETS uses the known task cost or reward, an undiscounted finite horizon, and no learned terminal critic. Writing it as reward maximization,

$$
\hat J^{(i)}=
\frac1P\sum_{p=1}^P
\sum_{j=0}^{H-1}
r\left(s_j^{(i,p)},u_j^{(i)},s_{j+1}^{(i,p)}\right).
$$

Here the known reward may depend on the realized next state, so it is evaluated separately on each particle. The candidate sequence is shared across particles. Their states differ because of model uncertainty and stochastic transitions.

Do not average particles into one state before evaluating reward. Reward at the mean state can differ substantially from mean reward.

### TS1 and TS-Infinity

Trajectory sampling also specifies how particles use ensemble members.

**TS1** resamples the ensemble member at every simulated step. A particle can use one model for its first transition and another for the next.

**TS-infinity** chooses a member for each particle and keeps that member fixed throughout its simulated trajectory. The particle still samples stochastic outcomes from that member. A fixed model index does not make the trajectory deterministic.

TS-infinity preserves a consistent hypothesis about dynamics over time. If one model predicts a light cart and another a heavy cart, a fixed-member particle remains a trajectory of one cart type. TS1 mixes hypotheses step by step. The choice affects the trajectory distribution. Neither procedure turns an approximate ensemble into an exact Bayesian posterior.

Within-member randomness and between-member disagreement originate differently in the fitted model. Keeping particles separate allows their consequences for return to remain visible.

## One Complete Learning Iteration

Suppose the cart has collected an initial dataset using a simple exploratory controller. A PETS-style iteration proceeds as follows.

First, fit the ensemble on real transitions. Reserve appropriate held-out data to detect poor fit and overtraining. If state normalization is used, keep training and prediction transformations consistent.

Second, at the current real state, initialize the CEM action distribution. For each CEM iteration, sample candidate sequences, evaluate particle trajectories, select elites, and refit the proposal.

Third, execute the first action of the selected plan. Record the observed transition in the real dataset. Replan from the next observed state. Refit dynamics periodically as more data become available.

~~~text
real transitions -> ensemble fitting -> candidate trajectory evaluation
       ^                                      |
       |                               first planned action
       |                                      |
       +------------ environment <------------+
~~~

There is no separately trained actor or critic in original PETS. Its action-selection computation is the planner. PETS and [MBPO](/docs/04-model-based/dyna-and-learned-models) share a dynamics-model family, but MBPO uses synthetic transitions to train an actor that selects actions without this trajectory optimizer.

In the pinned PETS implementation, CEM returns its fitted mean sequence and the MPC controller executes the first action of that mean. For implementation reading, begin with the pinned [MPC controller](https://github.com/kchua/handful-of-trials/blob/77fd8802cc30b7683f0227c90527b5414c0df34c/dmbrl/controllers/MPC.py). Find the optimizer call, prediction propagation, task cost, and sequence shift. Then read the CEM file and [probabilistic network](https://github.com/kchua/handful-of-trials/blob/77fd8802cc30b7683f0227c90527b5414c0df34c/dmbrl/modeling/models/BNN.py). Reading only the network misses the controller.

## Choosing a Horizon

A short horizon limits accumulated prediction error and computation. It can also be shortsighted. If moving away from the target now is necessary to go around a wall, an overly short objective may never reward that maneuver.

A longer horizon exposes delayed consequences but increases search dimension, particle cost, and model error. More candidates can improve optimization while increasing the chance of finding an optimistic model mistake.

A terminal value offers a different compromise:

$$
\text{short modeled prefix}
\quad+\quad
\text{estimated value of what follows}.
$$

It exchanges some dynamics error for critic error. The critic must be accurate at the planner's endpoints, which may differ from replay states. [TD-MPC](/docs/04-model-based/latent-model-based-rl) explores this combination explicitly. It is not an automatic fix obtained by appending an arbitrary value network.

Also distinguish planning horizon from control frequency. Replanning every action and replanning every five actions are different controllers even if they optimize the same horizon. Latency can make an otherwise attractive planner unsuitable for a fast physical system.

## Expected Return, Risk, and Constraints

A particle average estimates expected return under the fitted predictive distribution. It does not ensure that every particle avoids an obstacle, that rare events are represented, or that the fitted distribution matches the real system.

Risk-sensitive planning could optimize a lower return quantile or penalize return variance. Constrained MPC could reject trajectories violating modeled limits. Robust MPC can optimize against specified uncertainty sets. Each requires a precise objective and assumptions. None follows merely from using an ensemble.

Action bounds limit the force the actuator is commanded to apply. State constraints are harder because their satisfaction depends on uncertain future dynamics. Safety guarantees require additional control-theoretic conditions and a credible uncertainty model.

For a learning experiment, first ask what the planner actually optimizes and what violations were measured. A low average task cost can hide occasional severe failures.

## Diagnose the Right Component

When performance is poor, separate the model, objective, and optimizer.

If planning with the true simulator succeeds while planning with fitted dynamics fails, investigate prediction and distribution shift. If both fail at the same compute budget, the horizon or optimizer may be inadequate. If modeled returns improve while real returns deteriorate as search increases, model exploitation is a plausible diagnosis.

These are informative ablations, not complete proofs. A true dynamics model still leaves finite search, an imperfect terminal critic if one is used, and possibly an unsuitable reward.
