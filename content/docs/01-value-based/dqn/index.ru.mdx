> **Аннотация.** DQN сохраняет обновление Q-Learning из предыдущей главы, но заменяет таблицу нейронной сетью $Q_\theta(s,a)$. Обучение наивно не работает: сочетание аппроксимации функции, bootstrapping и данных off-policy создает нестабильность. DQN решает эту проблему с помощью двух дополнений — воспроизведения опыта и целевой сети — каждое из которых направлено на отдельный режим сбоя.

В таблице Q-Learning хранится одно число для каждой пары состояние-действие. Эта таблица полезна для «Хождения по скале», поскольку в сетке есть несколько состояний и четыре действия. Оно перестает работать, когда состояние представляет собой непрерывный вектор наблюдения. CartPole имеет четырехмерное состояние; Atari использует необработанные кадры изображений. В обоих случаях одно и то же состояние может никогда не повториться, поэтому таблица не может быть обобщена.

Ход DQN сформулировать просто: аппроксимировать функцию «действие-значение» с помощью нейронной сети. Вместо явного сохранения $Q(s,a)$ изучите параметры $\theta$ из $Q_\theta(s,a)$. Для дискретного пространства действий обычная архитектура принимает состояние в качестве входных данных и выводит один скаляр для каждого действия — один прямой проход дает значения Q для каждого действия одновременно.

Жадным действием по-прежнему является $\arg\max_a Q_\theta(s,a)$, поэтому DQN остается value-based. Пространство действий должно быть достаточно дискретным, чтобы все значения действий помещались в один прямой проход.

## Q-Learning как проблема регрессии

С этого момента мы компактно записываем переход как $(s, a, r, s')$ — сокращение от $(S_t, A_t, R_{t+1}, S_{t+1})$ с опущенным временным индексом.

Основная идея состоит в том, чтобы использовать Q-Learning как регрессию с учителем. Уравнение оптимальности Беллмана (из главы MDP) гласит, что оптимальная функция действия-ценности удовлетворяет следующим условиям:

$$
q_*(s, a) = \mathbb{E}\!\left[r + \gamma \max_{a'} q_*(s', a')\right],
$$

где ожидание превышает случайное вознаграждение $r$ и следующее состояние $s'$ из окружающей среды. Для выборочного перехода $(s,a,r,s')$ правая часть дает одновыборочную оценку того, каким должен быть $Q_\theta(s,a)$. Мы используем его в качестве цели обучения и минимизируем квадрат ошибки:

$$
y = r + \gamma \max_{a'} Q_\theta(s', a'), \qquad L(\theta) = \mathbb{E}_{(s,a,r,s')}\!\left[\bigl(y - Q_\theta(s,a)\bigr)^2\right].
$$

Думайте об этом как об обучении с учителем с движущейся меткой. Входными данными является состояние, выходными данными является значение Q для выбранного действия, а $y$ играет роль цели регрессии. В обычной регрессии цель берется из фиксированного набора данных; здесь он вычисляется из той же сети, которую мы пытаемся обучить.

Одна тонкость: градиент должен проходить только через предсказание $Q_\theta(s,a)$, а не через $y$. Это обновление **полуградиент**: $y$ на этом этапе рассматривается как фиксированная константа, хотя она зависит от $\theta$. Обратное распространение в $y$ приведет к тому, что обновление будет стремиться к самореферентной согласованности, а не к какому-либо внешнему сигналу Беллмана.

Более глубокая проблема скрыта в целевой формуле: и прогноз $Q_\theta(s,a)$, и целевой $y$ зависят от одного и того же $\theta$. Каждый шаг градиента меняет $\theta$, что немедленно смещает преследуемую цель $y$. Оптимизатор преследует движущуюся цель: каждое обновление меняет цель, поэтому следующее обновление должно преследовать немного другое значение, и сеть никогда не стабилизируется. На практике эта версия расходится или колеблется — она просто не работает.

Причиной неудачи являются две структурные проблемы. Оставшаяся часть главы посвящена каждому из них.

## Смертельная триада

Прежде чем называть исправления, полезно назвать основную причину. DQN находится на **смертельная триада**, опасность нестабильности и расхождения возникает всякий раз, когда мы объединяем все эти три элемента:

1. **Аппроксимация функции** — одна сеть представляет множество значений действий состояния через общие параметры.
2. **Bootstrapping** — цель содержит еще одну оценку полученного значения, $\max_{a'} Q(s',a')$.
3. **off-policy обучение** — данные могут поступать из более старых исследовательских политик, хотя цель является жадной.

Каждый компонент ценен по отдельности. Вместе, особенно с нелинейными сетями, они могут вызвать колебания или расхождения: обновление одной части сети распространяет изменения на другие состояния через общие веса, эти измененные оценки становятся целями для дальнейших обновлений, а сохраненные данные могут не соответствовать текущей политике. Смертельная триада не устраняется DQN, ее укрощают два стабилизатора, по одному на каждый из приведенных ниже режимов отказа.

## Проблема 1: Коррелированные выборки

Первая проблема: переходы, собранные онлайн, не являются i.i.d, они сильно коррелированы во времени. В Atari последовательные кадры отличаются всего на несколько пикселей: агент все еще находится в той же комнате, те же враги почти на тех же позициях. Мини-пакет последовательных переходов, по сути, представляет собой повторение одного и того же наблюдения.

Это вызывает две проблемы. Когда все образцы взяты из одной и той же части игры, шаги градиента указывают примерно в одном направлении, и сеть продолжает уточнять один и тот же узкий фрагмент опыта. А когда агент перемещается в новый регион, веса начинают соответствовать новым данным, а старые знания перезаписываются. Сеть забывает. На практике это проявляется в виде неровной кривой обучения: производительность растет, пока агент остается в одной области, а затем падает, когда он движется дальше.

Есть вторая проблема. Каждый переход используется ровно один раз, а затем отбрасывается. Это расточительно: редкий, но информативный переход, вызвавший большую ошибку TD, получает один шаг градиента и больше никогда не наблюдается.

**Опыт повтора** решает обе проблемы. Каждый переход, который собирает агент, сохраняется в конечном буфере $\mathcal{D}$:

$$
(s_t, a_t, r_t, s_{t+1}).
$$

/>

Обучение извлекает из этого буфера однородные случайные мини-пакеты. Поскольку переходы выбираются случайным образом, каждый мини-пакет смешивает данные из разных эпизодов и разных этапов обучения, что нарушает временные корреляции. Один и тот же переход может также присутствовать в нескольких мини-пакетах, что повышает эффективность данных.

Воспроизведение естественным образом работает с Q-Learning, поскольку Q-Learning — это off-policy. Переход, собранный тысячи шагов назад при большем весе $\epsilon$ и более старых, по-прежнему является действительными данными обучения: цель является жадной по отношению к $s'$ и не зависит от того, что старая политика поведения будет делать дальше.

## Проблема 2: движущаяся цель

Воспроизведение декоррелирует данные. Это не решает другую проблему: целевой $y = r + \gamma \max_{a'} Q_\theta(s', a')$ вычисляется из той же сети, которая обновляется. Каждый шаг градиента перемещает $\theta$, который перемещает $y$, что меняет картину потерь, над которой только что работал оптимизатор.

**Target network** решает эту проблему: вводится вторая, медленно обновляемая копия сети с параметрами $\theta^-$, которая используется только для вычисления bootstrapped-цели. **Online network** с параметрами $\theta$ обновляется на каждом шаге градиента. При замороженном $\theta^-$ цель принимает вид:

$$
y = r + \gamma \max_{a'} Q_{\theta^-}(s', a').
$$

Поскольку $\theta^-$ остается фиксированным для многих обновлений, цель остается неподвижной достаточно долго, чтобы блок шагов градиента напоминал обычную регрессию с фиксированной целью.

При **жёстком обновлении** веса target network заменяются весами online network каждые $C$ шагов градиента:

$$
\theta^- \leftarrow \theta.
$$

Nature DQN использовал $C = 10{,}000$. Альтернативой является **мягкое обновление Поляка**, применяемый на каждом этапе с небольшим коэффициентом смешивания $\tau$:

$$
\theta^- \leftarrow \tau\,\theta + (1 - \tau)\,\theta^-.
$$

Так target network постепенно приближается к online network. В DQN стандартно используется жёсткое копирование; мягкие обновления появятся в методах непрерывного управления из главы 3.

## Exploration с помощью расписания $\epsilon$

DQN собирает данные с помощью $\epsilon$-greedy политики с убывающим $\epsilon$. В начале обучения $\epsilon$ велик, поэтому replay buffer наполняется разнообразными исследовательскими переходами. Затем $\epsilon$ снижается до минимального значения: агент в основном следует обученной Q-функции, но продолжает собирать новый опыт.

Скорость затухания имеет значение: если $\epsilon$ падает слишком быстро, буфер заполняется почти жадными данными до того, как Q-функция станет достаточно надежной, чтобы направлять их. Если он падает слишком медленно, в тренировках повсюду преобладают случайные действия. На практике линейное затухание работает хорошо. Правильная продолжительность зависит от окружающей среды: она должна охватывать, по крайней мере, период, когда Q-функция все еще слишком ненадежна, чтобы самостоятельно руководить исследованием.

## Тренировочный цикл

При наличии воспроизведения, целевой сети и расписания $\epsilon$ полный алгоритм DQN поочередно выполняет действия, сохраняет и обучается:

```
initialize Q_theta and Q_theta_minus with the same random weights
initialize replay buffer D

for each environment step:
    choose action a with epsilon-greedy(Q_theta(s))
    step environment, observe r, s', done
    store (s, a, r, s', done) in D

    if |D| >= batch_size:
        sample a uniform minibatch from D
        for terminal transitions:     y = r
        for non-terminal transitions: y = r + gamma * max_a' Q_theta_minus(s', a')
        update theta to minimize (y - Q_theta(s, a))^2

    every C steps: copy theta into theta_minus
```

Несколько вещей, которые стоит отметить. Обе сети начинаются с одинаковых весов: целью является не отдельная случайная инициализация, а просто замороженная копия онлайн-сети. Обучение начинается только после того, как буфер соберет достаточное количество переходов; на раннем этапе агент просто действует и сохраняет. Для терминальных переходов термин bootstrapping полностью отбрасывается: эпизод окончен, поэтому нет следующего состояния для оценки. Целевая синхронизация каждые шаги $C$ — это единственный момент перемещения целевой сети; между синхронизациями полностью зависает.

## Пример: CartPole

**CartPole-v1** — это стандартная проверка работоспособности для глубоких методов value-based. Состояние представляет собой четырехмерный вектор: положение тележки, скорость тележки, угол шеста и угловая скорость шеста; и в пространстве действий есть два варианта: нажать влево или нажать вправо. Эпизод заканчивается, когда угол наклона столба превышает 12 градусов или тележка вылетает за пределы экрана. Идеальный эпизод длится 500 шагов и приносит доход в размере 500.

<img
  src="/docs-assets/01-value-based/dqn/cartpole-demo.gif"
  alt="Обученный агент DQN балансирует шест на CartPole-v1"
  style={{ maxWidth: '70%', margin: '2rem auto', display: 'block' }}
/>

Q-сеть — это MLP с двумя скрытыми слоями, который отображает четырехмерное состояние в два значения Q — по одному на действие:

```python
class QNetwork(nn.Module):
    """Two-hidden-layer MLP: state -> Q-value for each discrete action."""

    def __init__(self, state_dim: int, hidden_dim: int, n_actions: int) -> None:
        super().__init__()
        self.fc1 = nn.Linear(state_dim, hidden_dim)
        self.fc2 = nn.Linear(hidden_dim, hidden_dim)
        self.out = nn.Linear(hidden_dim, n_actions)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """Forward pass: state -> Q-values over actions."""
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        return self.out(x)
```

Один проход вперед создает значения Q для обоих действий, и `argmax` выбирает жадный выбор. Функция потерь представляет собой квадрат ошибки TD из предыдущих разделов, градиент течет только через онлайн-прогнозирование:

```python
def compute_td_loss(
    q_net: QNetwork,
    target_net: QNetwork,
    states: torch.Tensor,
    actions: torch.Tensor,
    rewards: torch.Tensor,
    next_states: torch.Tensor,
    dones: torch.Tensor,
    gamma: float,
) -> torch.Tensor:
    """One-step DQN squared TD-error loss."""
    q_values = q_net(states).gather(1, actions.unsqueeze(1)).squeeze(1)
    with torch.no_grad():
        next_q = target_net(next_states).max(dim=1).values
        targets = rewards + gamma * (1.0 - dones) * next_q
    return F.mse_loss(q_values, targets)
```

`gather` выбирает значение Q для фактически выполненного действия. `torch.no_grad()` в целевом блоке гарантирует, что $\theta^-$ обрабатывается как константа: никакие градиенты не текут обратно через целевой блок.

В эксперименте используется 600 эпизодов со скрытым измерением 128, скоростью обучения $2 \times 10^{-3}$, скидкой $\gamma = 0.99$ и буфером воспроизведения емкостью 10 000. Обучение начинается, когда в буфере будет 500 переходов. Целевая сеть синхронизирует каждые 50 обновлений градиента. Эпсилон линейно затухает от 1,0 до 0,05 в течение первых 5000 шагов среды.
