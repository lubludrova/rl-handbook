> **Аннотация.** Предыдущая глава закончилась уравнениями Беллмана. Динамическое программирование — это первый способ превратить эти уравнения в алгоритмы. Когда конечная модель MDP известна, мы можем планировать, просматривая состояния, обновляя каждое значение на основе одношаговых прогнозов модели и жадно улучшая политику. В этой главе строится цикл оценки-улучшения, лежащий в основе итерации политики, а затем показано, как итерация ценности объединяет две одни и те же идеи в одно обновление.

Динамическое программирование (ДП) — это набор алгоритмов для вычисления хороших или оптимальных политик, когда окружающая среда уже задана как конечный марковский процесс принятия решений. Предположение намеренно сильное: наборы состояний, действий и вознаграждений конечны, и агент знает полную одношаговую динамику $p(s', r \mid s, a)$. В этом случае проблема заключается не в изучении окружающей среды на основе опыта, а в использовании известной модели для планирования. Таким образом, классический DP ограничен как практический метод обучения с подкреплением: реальные среды часто неизвестны, велики или непрерывны. Но это по-прежнему лучшее место, где можно увидеть вычислительную структуру, аппроксимируемую более поздними алгоритмами.

Ключевая идея DP и большей части обучения с подкреплением заключается в использовании функций стоимости для организации поиска хороших политик. В предыдущей главе мы определили $v_\pi$, $q_\pi$ и функции оптимального значения $v_*$ и $q_*$, а затем написали уравнения оптимальности Беллмана, которым они должны удовлетворять:

$$
v_*(s) = \max_a \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_*(s')\right]
$$

$$
q_*(s,a) = \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma \max_{a'} q_*(s',a')\right]
$$

ДП начинается с этих уравнений. Как только $v_*$ или $q_*$ известны, извлечение оптимальной политики становится простым: выбирайте действия, которые являются жадными по отношению к оптимальным значениям. Остается вопрос, как вычислить эти значения. DP отвечает, превращая уравнения Беллмана в правила обновления, которые улучшают аппроксимацию функций желаемого значения.

## Оценка политики

Сначала мы рассмотрим, как вычислить функцию значения состояния $v_\pi$ для произвольной фиксированной политики $\pi$. В литературе по динамическому программированию это называется **оценка политики**. Его также называют **проблема прогнозирования**, поскольку политика еще не совершенствуется: мы только прогнозируем доход, который следует ожидать, если агент следует $\pi$ из каждого состояния.

Из главы MDP уравнение ожидания Беллмана выглядит следующим образом:

$$
v_\pi(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_\pi(s')\right]
$$

Это уравнение неявно определяет $v_\pi$. Неизвестное значение появляется с обеих сторон: значение состояния $s$ зависит от значений последующих состояний $s'$, значения которых также неизвестны. Для конечного MDP это система одновременных уравнений, по одному уравнению для каждого состояния. В принципе, мы могли бы решить эту систему напрямую, но в динамическом программировании используется итеративный подход, который ближе к алгоритмам, которые мы будем повторно использовать позже.

**Итеративная оценка политики** начинается с произвольной функции приближенного значения, скажем, $v_0$. Первоначальные цифры не обязательно должны быть хорошими; состояния терминала, если они присутствуют, сохраняются в значении $0$, поскольку после завершения не остается будущего вознаграждения. Каждое новое приближение $v_{k+1}$ создается на основе предыдущего приближения $v_k$ с использованием уравнения ожидания Беллмана в качестве правила обновления: замените текущую оценку состояния ожидаемым вознаграждением за один шаг плюс дисконтированную оценочную стоимость того, что будет дальше.

$$
v_{k+1}(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_k(s')\right]
$$
Целью этого процесса является функция значения, которая больше не изменяется при обновлении. Если наше текущее приближение уже соответствует истинному $v_\pi$, применение обновления ожиданий Беллмана снова вернет те же значения. В этом смысле $v_\pi$ — это **фиксированная точка** обновления. Прежде чем мы достигнем этого, каждая итерация делает оценки более согласованными с политикой и моделью.

Один полный проход по всем состояниям называется **sweep**. В ходе sweep старое значение каждого состояния заменяется новым, вычисленным по одношаговым исходам модели. Это обновление использует **bootstrapping**: одна оценка обновляется через другие оценки. Значение текущего состояния $s$ зависит от текущих $v_k(s')$ возможных следующих состояний, а не от полного return эпизода $G_t$. При повторных sweep информация о ценности распространяется назад по пространству состояний.
## Улучшение политики

Оценка говорит нам, насколько хороша политика. Улучшение спрашивает, как сделать его лучше. Причина, по которой мы вычислили $v_\pi$, заключалась не только в описании текущей политики, но и в проверке возможных изменений в ней.

Предположим, что $v_\pi$ известен по текущей политике $\pi$. В состоянии $s$ политика в настоящее время может выбрать одно действие или распределение по действиям. Чтобы задаться вопросом, лучше ли другое действие $a$, мы оцениваем отклонение в один шаг: берем $a$ один раз в $s$, а затем возвращаемся к следующему $\pi$. Ценность этого выбора — это ценность действия в соответствии со старой политикой:

$$
q_\pi(s,a) = \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_\pi(s')\right]
$$

Сравните это число с $v_\pi(s)$. Если $q_\pi(s,a) > v_\pi(s)$, то взять $a$ один раз и следовать за $\pi$ потом лучше, чем сразу следовать за $\pi$ из $s$. Это одноэтапное сравнение представляет собой локальный тест, используемый для улучшения политики.

Простой способ построить такую политику — проявить жадность по отношению к $q_\pi$:

$$
\pi'(s) = \arg\max_a q_\pi(s,a)
$$

Жадная политика выбирает действие, немедленное вознаграждение которого плюс дисконтированная стоимость продолжения является наибольшим, при этом стоимость продолжения по-прежнему измеряется с помощью $v_\pi$. По построению этот выбор удовлетворяет

$$
q_\pi(s, \pi'(s)) = \max_a q_\pi(s,a) \geq v_\pi(s),
$$

потому что $v_\pi(s)$ — это среднее значение старой политики для тех же значений действия. Затем **Теорема об улучшении политики** дает глобальный вывод:

$$
v_{\pi'}(s) \geq v_\pi(s) \quad \text{for all } s
$$

Мы будем использовать теорему как гарантию, а не доказывать ее. Интуиция подсказывает, что шаг по улучшению не обязательно должен предвидеть все будущее с нуля. Функция значения $v_\pi$ уже суммирует то, что произойдет после первого шага, если мы продолжим использовать старую политику. Таким образом, улучшение требует только одного: какое из доступных первых действий дает наилучшее немедленное вознаграждение плюс сниженную ценность продолжения старой политики?

<Callout title="Что, если политика стохастическая?" type="info">
Оценка политики уже обрабатывает стохастические политики через $\pi(a \mid s)$. На этапе улучшения мы для ясности используем детерминированные жадные политики: выбираем действие, которое максимизирует $q_\pi(s,a)$. Если несколько действий совпадают с максимумом, стохастическая жадная политика может разделить вероятность между этими лучшими действиями, присвоив нулевую вероятность действиям ниже максимума. Теорема улучшения политики все еще применима.
</Callout>

## Итерация политики

**Итерация политики** чередует эти два процесса:

1. **Оценка политики:** вычисляет $v_\pi$ для текущей политики.
2. **Улучшение политики:** делает политику жадной по отношению к этой функции значения.
3. Повторяйте до тех пор, пока политика не перестанет меняться.

Когда политика после улучшения становится стабильной, она является жадной по отношению к своей собственной функции ценности. В этот момент уравнения ожидания Беллмана и оптимальности совпадают, поэтому политика оптимальна.

В конечных MDP итерация политики достигает оптимальной политики после конечного числа улучшений. Эта глава не нуждается в доказательствах; оперативной картины достаточно: оценить, улучшить, оценить, улучшить.

Этот цикл оценки-улучшения является более общим, чем алгоритм чистой итерации политики. Оценка пытается привести функцию стоимости в соответствие с текущей политикой. Улучшение пытается сделать политику жадной по отношению к функции текущего значения. Эти два процесса взаимодействуют: после улучшения старая функция стоимости уже не совсем корректна для новой политики; после того, как оценка изменит значения, текущая политика больше не может быть жадной.

Это взаимодействие называется **итерация обобщенной политики**. Полная итерация политики разделяет два процесса на большие блоки: оценить, затем улучшить. Более поздние алгоритмы чередуют их более плотно. Итерация значения включает улучшение в каждое обновление значения; Методы контроля временной разницы в конечном итоге выполняют аналогичное взаимодействие оценки и улучшения на основе выборочных переходов, а не полных разверток model-based.

## Итерация значения

Итерация политики оценивает каждую промежуточную политику перед ее улучшением. Это чисто, но может быть расточительно: итеративная оценка политики может потребовать многих проверок, и оцениваемая политика может быть изменена сразу после этого. Естественный вопрос заключается в том, действительно ли оценки должны совпадать, прежде чем произойдет улучшение.

Это не так. Оценка политики может быть **усеченный**: мы можем остановиться после нескольких проверок, улучшить политику и продолжить. **Итерация значения** — наиболее сжатая версия этой идеи. Он прекращает оценку после одного обновления каждого состояния и включает в это обновление этап улучшения, выполняя максимальное количество действий:

$$
v_{k+1}(s) = \max_a \sum_{s',r} p(s', r \mid s, a) \left[r + \gamma v_k(s')\right]
$$

Это обновление имеет почти ту же форму, что и оценка политики. Разница в $\max_a$. Оценка политики усредняет действия, выбранные фиксированной политикой $\pi$; итерация значения спрашивает, какое действие будет лучшим в соответствии с текущими значениями-преемниками. В этом смысле итерация значений превращает уравнение оптимальности Беллмана непосредственно в правило обновления.

После повторных проверок значения приближаются к $v_*$. Затем из конечной функции значения извлекается жадная политика:

$$
\pi^*(s) = \arg\max_a \sum_{s',r} p(s', r \mid s, a) \left[r + \gamma v_*(s')\right]
$$

В небольших задачах, таких как прогулка по скале, итерация значения часто требует меньшего количества общих циклов, чем полная итерация политики, поскольку она не оценивает каждую промежуточную политику с высокой точностью. Оба метода сходятся к одной и той же функции оптимального значения $v_*$ и оптимальной политике.

## Почему важно динамическое программирование

Динамическое программирование имеет два ограничения. Во-первых, ему нужна полная модель $p(s', r \mid s,a)$. Во-вторых, каждый проход затрагивает пространство состояний, что становится невозможным, когда $\mathcal{S}$ огромен.

Его ценность в том, что он дает шаблон для всего последующего. Методы Монте-Карло удалят модельные и оценочные значения из полных выборочных доходов. Методы временной разницы сохранят идею bootstrapping, но будут использовать переходы с одной выборкой. Q-Learning будет применять резервную копию оптимальности Беллмана непосредственно к выборочным значениям действий.

В этом смысле динамическое программирование является точным табличным ориентиром: если модель известна и достаточно мала, решите MDP с помощью резервных копий Беллмана. Если модель неизвестна или слишком велика, примените ту же логику, исходя из опыта.

## Замечания по реализации

Полный пример сохраняет явную модель MDP. `transitions[state, action, next_state]` хранит $p(s' \mid s,a)$, а `rewards[state, action, next_state]` хранит вознаграждение, связанное с этим переходом. Это соответствует суммам Беллмана, приведенным выше: для каждого действия код может умножить каждое возможное следующее состояние как на его вероятность, так и на вознаграждение за переход. Cliff Walking является детерминированным, поэтому каждая пара `(state, action)` имеет вероятность `1.0` ровно в одном следующем состоянии, но представление также поддерживает стохастические переходы, помещая массу вероятности в несколько следующих состояний.

```python
transitions = np.zeros((n_states, n_actions, n_states))
rewards = np.zeros((n_states, n_actions, n_states))
action_deltas = [(-1, 0), (0, 1), (1, 0), (0, -1)]  # up, right, down, left
```

Основное вычисление — это одношаговый просмотр вперед. Для фиксированного состояния он вычисляет ожидаемое одношаговое вознаграждение за каждое действие плюс дисконтированную стоимость последующего действия:

```python
def one_step_lookahead(
    state: int,
    values: np.ndarray,
    transitions: np.ndarray,
    rewards: np.ndarray,
    gamma: float,
) -> np.ndarray:
    """Compute action values from one Bellman backup in a single state."""
    return np.sum(transitions[state] * (rewards[state] + gamma * values), axis=1)
```

Оценка политики усредняет значения этих действий в рамках текущей политики:

```python
action_values = one_step_lookahead(state, old_values, transitions, rewards, gamma)
values[state] = policy[state] @ action_values
```

Итерация значений использует те же значения действий, но заменяет среднее значение политики максимальным:

```python
action_values = one_step_lookahead(state, old_values, transitions, rewards, gamma)
values[state] = np.max(action_values)
```

В обоих фрагментах используется **синхронная развертка**: код копирует `old_values`, затем вычисляет каждое новое значение на основе значений предыдущей развертки. Это соответствует индексированному обозначению $v_{k+1}$ из $v_k$, используемому в приведенных выше уравнениях. Порог остановки $\theta$ реализуется путем измерения максимального изменения значения при развертке:

```python
if np.max(np.abs(values - old_values)) < theta:
    return values, sweep + 1
```

Сценарий возвращает счетчики разверток, поэтому выходные данные терминала могут сравнить объем работы, выполненной при итерации политики и итерации значения. Он использует $\gamma = 0.9$ и $\theta = 10^{-3}$ для читаемого демонстрационного вывода, затем печатает функцию окончательного значения в виде сетки $4 \times 12$ и печатает жадные политики, найденные обоими методами. Это отражает способ частой проверки табличного DP: значения показывают, как информация о вознаграждении распространяется по сетке, а политики показывают, какие действия являются жадными после планирования.

Улучшение политики и окончательное извлечение политики имеют одного и того же помощника. Сначала вычислите значения всех одношаговых действий, затем примените массу вероятности к максимизирующим действиям. Если несколько действий совпадают, код равномерно распределяет вероятность между ними; вот почему напечатанная политика может отображать несколько стрелок в одной ячейке.

```python
q_values = np.zeros((n_states, n_actions))
policy = np.zeros((n_states, n_actions))

for state in range(n_states):
    q_values[state] = one_step_lookahead(state, values, transitions, rewards, gamma)
    best_value = q_values[state].max()
    best_actions = np.flatnonzero(np.isclose(q_values[state], best_value))
    policy[state, best_actions] = 1.0 / len(best_actions)
```

Полный синхронный sweep — не единственный возможный график DP. При асинхронном обновлении значения меняются на месте, поэтому следующие состояния в том же проходе уже могут использовать новые оценки. Это всё ещё динамическое программирование, если каждое состояние обновляется достаточно часто. Такой график полезен, когда часть состояний важнее остальных и вычисления можно сосредоточить на них. Здесь мы не разбираем prioritized sweeping; достаточно понимать, что обновления Беллмана не обязаны выполняться равномерными полными проходами.
