> **摘要.** 上一章以贝尔曼方程收尾。动态规划是把那些方程变成算法的第一种方式。当有限 MDP 模型已知时，我们可以通过遍历状态、用模型的一步预测更新每个价值、并贪婪地改进策略来进行规划。本章构建了策略迭代背后的"评估–改进"循环，然后展示值迭代如何把这两个思想合并为单次更新。

动态规划（DP）是一类算法，用于在环境已经作为有限马尔可夫决策过程给出的前提下，计算良好或最优的策略。这个假设刻意很强：状态、动作和奖励集合都是有限的，且智能体知道完整的一步动态 $p(s', r \mid s, a)$。在这种设定下，问题不是从经验中学习环境，而是用已知模型进行规划。因此经典 DP 作为一种实用的强化学习方法很受限：真实环境常常未知、庞大或连续。但它仍是观察后续算法所近似的计算结构最清晰的地方。

DP 以及强化学习很大一部分的关键思想，是用价值函数来组织寻找好策略的搜索。在上一章中我们定义了 $v_\pi$、$q_\pi$ 以及最优价值函数 $v_*$ 和 $q_*$，然后写下了它们必须满足的贝尔曼最优方程：

$$
v_*(s) = \max_a \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_*(s')\right]
$$

$$
q_*(s,a) = \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma \max_{a'} q_*(s',a')\right]
$$

DP 从这些方程出发。一旦知道了 $v_*$ 或 $q_*$，提取最优策略就很简单：选择相对于最优价值贪婪的动作。剩下的问题是如何计算那些价值。DP 的回答是：把贝尔曼方程变成更新规则，从而改进所需价值函数的近似值。

## 实验：悬崖行走

我们将使用 **悬崖行走**（Cliff Walking，Sutton 和 Barto，例 6.6）作为具体的 MDP。网格为 $4 \times 12$。起始状态是左下角格子，目标是右下角格子，它们之间底行的格子是悬崖。

每次移动通常给出奖励 $-1$。踏入悬崖给出奖励 $-100$ 并把智能体送回起点。到达目标则结束片段。转移模型是确定性的：如果智能体从非边缘格子向右移动，下一状态是精确已知的。

在可运行示例中，掉入悬崖被表示为一个奖励 $-100$ 的转移，其下一状态是起始格子。悬崖格子仍然存在于表中以便打印网格，但规划出的轨迹永远不会从它们继续：惩罚转移已经把智能体重定向回了起点。

这个示例让规划问题可见。一条沿着底行的、看起来贪婪的最短路径是危险的，因为一步走错就会掉进悬崖。已知 MDP 的最优策略会绕开悬崖并安全到达目标。

## 策略评估

我们首先考虑如何计算任意固定策略 $\pi$ 的状态价值函数 $v_\pi$。在动态规划文献中这被称为 **策略评估**（policy evaluation）。它也被称为 **预测问题**，因为策略尚未被改进：我们只是在预测，如果智能体从每个状态遵循 $\pi$，应期望得到多少回报。

根据 MDP 一章，贝尔曼期望方程是：

$$
v_\pi(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_\pi(s')\right]
$$

这个方程隐式地定义了 $v_\pi$。未知价值出现在等式两侧：状态 $s$ 的价值依赖于后继状态 $s'$ 的价值，而它们的价值也未知。对于一个有限 MDP，这是一个联立方程组，每个状态一个方程。原则上我们可以直接求解这个方程组，但动态规划使用的是迭代方法，它更接近我们之后会复用的算法。

**迭代策略评估**（iterative policy evaluation）从一个任意的近似价值函数出发，比如 $v_0$。初始数值不必很好；如果存在终止状态，则保持在价值 $0$，因为终止之后没有未来奖励了。每个新的近似 $v_{k+1}$ 都通过把贝尔曼期望方程当作更新规则，由前一个近似 $v_k$ 产生：用期望的一步奖励加上对后续内容的折扣估计价值，替换掉一个状态的当前估计。

$$
v_{k+1}(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_k(s')\right]
$$

这个过程的目的是达到一个在更新下不再改变的价值函数。如果我们当前的近似已经匹配了真实的 $v_\pi$，那么施加贝尔曼期望更新会再次返回相同的值。在这个意义上，$v_\pi$ 是更新的 **不动点**（fixed point）。在到达它之前，每次迭代都让估计与策略和模型更一致。

对全部状态的一次完整遍历称为一次 **扫描**（sweep）。在一次扫描中，每个状态的旧值被用模型一步结果计算出新值所替换。这个更新也是 **自举**（bootstrapping）的。这个术语意味着用一个估计来更新另一个估计。这里，当前状态 $s$ 的价值是用可能的下一状态 $s'$ 的当前价值 $v_k(s')$ 来更新的，而不是等待完整的片段回报 $G_t$。因为每个状态都能把信息传回导向它的状态，价值信息会在反复扫描中穿过状态空间传播。

## 策略改进

评估告诉我们一个策略有多好。改进则问如何让它更好。我们计算 $v_\pi$ 的原因不只是为了描述当前策略，也是为了检验对它可能的改动。

假设 $v_\pi$ 对当前策略 $\pi$ 已知。在状态 $s$，策略当前可能选择一个动作，或一个动作上的分布。要问另一个动作 $a$ 是否更好，我们评估一次单步偏离：在 $s$ 采取 $a$ 一次，之后回到遵循 $\pi$。该选择的价值就是旧策略下的动作价值：

$$
q_\pi(s,a) = \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_\pi(s')\right]
$$

把这个数与 $v_\pi(s)$ 比较。如果 $q_\pi(s,a) > v_\pi(s)$，那么先采取 $a$ 一次、之后遵循 $\pi$，比从 $s$ 立即遵循 $\pi$ 更好。这个单步比较就是用于策略改进的局部检验。

构造这样一个策略的简单方法是相对于 $q_\pi$ 贪婪：

$$
\pi'(s) = \arg\max_a q_\pi(s,a)
$$

贪婪策略选择"即时奖励加上折扣的延续价值"最大的动作，其中延续价值仍用 $v_\pi$ 度量。按构造，这个选择满足

$$
q_\pi(s, \pi'(s)) = \max_a q_\pi(s,a) \geq v_\pi(s),
$$

因为 $v_\pi(s)$ 是旧策略在同一组动作价值上的平均。**策略改进定理**（policy improvement theorem）随后给出全局结论：

$$
v_{\pi'}(s) \geq v_\pi(s) \quad \text{for all } s
$$

我们会把该定理当作保证来使用，而不是证明它。直觉是，一次改进步骤不需要从头预见到整个未来。价值函数 $v_\pi$ 已经总结了如果我们沿用旧策略、第一步之后会发生什么。所以改进只问：在可用的第一步动作中，哪一个能给出最好的即时奖励加上折扣的旧策略延续价值？

<Callout title="如果策略是随机的怎么办？" type="info">
策略评估已经通过 $\pi(a \mid s)$ 处理了随机策略。在改进步骤中，为了清晰我们使用确定性贪婪策略：选择一个最大化 $q_\pi(s,a)$ 的动作。如果多个动作并列最大，一个随机贪婪策略可以在那些最好的动作之间分配概率，而对低于最大值的动作分配零概率。策略改进定理仍然适用。
</Callout>

## 策略迭代

**策略迭代**（policy iteration）交替执行这两个过程：

1. **策略评估：** 为当前策略计算 $v_\pi$。
2. **策略改进：** 让策略相对于该价值函数贪婪。
3. 重复直到策略不再改变。

当策略在改进后稳定时，它相对于自身的价值函数是贪婪的。此时，贝尔曼期望方程与最优方程一致，因此该策略是最优的。

在有限 MDP 中，策略迭代在经过有限次改进后达到最优策略。本章不需要证明；操作图景已经足够：评估、改进、评估、改进。

这个"评估–改进"循环比干净的策略迭代算法更通用。评估试图让价值函数与当前策略一致。改进试图让策略相对于当前价值函数贪婪。这两个过程相互作用：改进之后，旧的价值函数对新策略不再精确正确；评估改变了价值之后，当前策略可能不再贪婪。

这种相互作用被称为 **广义策略迭代**（generalized policy iteration）。完整的策略迭代把两个过程分成大块：先评估，再改进。后来的算法更紧密地交错它们。值迭代把改进折叠进每次价值更新；时序差分控制方法最终用采样的转移而非基于完整模型的扫描，执行类似的评估–改进交互。

## 值迭代

策略迭代在改进之前先评估每个中间策略。这很干净，但可能很浪费：迭代策略评估可能需要很多次扫描，而正在评估的策略可能紧接着就被改变。自然的问题是，评估是否真的必须在改进发生前收敛。

不必。策略评估可以 **截断**（truncated）：我们可以在几次扫描后停止，改进策略，然后继续。**值迭代**（value iteration）是这个思想压缩得最彻底的形式。它在每个状态只经过一次更新后就停止评估，并通过在动作上取最大值把改进步骤折叠进那次更新：

$$
v_{k+1}(s) = \max_a \sum_{s',r} p(s', r \mid s, a) \left[r + \gamma v_k(s')\right]
$$

这个更新与策略评估的形状几乎相同。区别在于 $\max_a$。策略评估对由固定策略 $\pi$ 选择的动作取平均；值迭代问根据当前的后继价值，哪个动作最好。在这个意义上，值迭代把贝尔曼最优方程直接变成了更新规则。

经过反复扫描，价值逼近 $v_*$。然后从一个最终价值函数中提取贪婪策略：

$$
\pi(s) = \arg\max_a \sum_{s',r} p(s', r \mid s, a) \left[r + \gamma v(s')\right]
$$

在像悬崖行走这样的小问题上，值迭代通常比完整的策略迭代需要更少的总扫描次数，因为它不会把每个中间策略都评估到高精度。两种方法都收敛到相同的最优价值函数 $v_*$ 和最优策略。

## 动态规划为何重要

动态规划有两个局限。第一，它需要完整的模型 $p(s', r \mid s,a)$。第二，每次扫描都要触及状态空间，当 $\mathcal{S}$ 巨大时这变得不可能。

它的价值在于它给出了后续一切内容的模板。蒙特卡洛方法将去掉模型，从完整采样的回报中估计价值。时序差分方法将保留自举思想，但使用单个采样的转移。Q-learning 将把贝尔曼最优备份直接应用于采样的动作价值。

在这个意义上，动态规划是精确的表格参照点：如果模型已知且足够小，就用贝尔曼备份求解 MDP。如果模型未知或太大，就从经验中近似同样的逻辑。

## 实现说明

完整示例显式保留 MDP 模型。`transitions[state, action, next_state]` 存储 $p(s' \mid s,a)$，`rewards[state, action, next_state]` 存储该转移关联的奖励。这与上面的贝尔曼求和一致：对每个动作，代码可以把每个可能的下一状态乘以它的概率和它的转移奖励。悬崖行走是确定性的，因此每个 `(state, action)` 对恰好在一个下一状态上有概率 `1.0`，但该表示也通过在多个下一状态上放置概率质量来支持随机转移。

```python
transitions = np.zeros((n_states, n_actions, n_states))
rewards = np.zeros((n_states, n_actions, n_states))
action_deltas = [(-1, 0), (0, 1), (1, 0), (0, -1)]  # 上、右、下、左
```

核心计算是一步前瞻。对于一个固定状态，它计算每个动作的期望一步奖励加上折扣的后继价值：

```python
def one_step_lookahead(
    state: int,
    values: np.ndarray,
    transitions: np.ndarray,
    rewards: np.ndarray,
    gamma: float,
) -> np.ndarray:
    """在单个状态中由一次贝尔曼备份计算动作价值。"""
    return np.sum(transitions[state] * (rewards[state] + gamma * values), axis=1)
```

策略评估在这些动作价值上按当前策略取平均：

```python
action_values = one_step_lookahead(state, old_values, transitions, rewards, gamma)
values[state] = policy[state] @ action_values
```

值迭代使用同样的动作价值，但用最大值替换策略平均：

```python
action_values = one_step_lookahead(state, old_values, transitions, rewards, gamma)
values[state] = np.max(action_values)
```

两个片段都使用 **同步扫描**（synchronous sweep）：代码复制 `old_values`，然后用上一次扫描的价值计算每个新价值。这与上面方程中从 $v_k$ 到 $v_{k+1}$ 的带索引记法一致。停止阈值 $\theta$ 通过比较一次扫描中最大的价值变化来实现：

```python
if np.max(np.abs(values - old_values)) < theta:
    return values, sweep + 1
```

脚本返回扫描次数，以便在终端输出中比较策略迭代和值迭代所完成的工作量。它使用 $\gamma = 0.9$ 和 $\theta = 10^{-3}$ 以获得可读的演示输出，然后把最终价值函数打印为 $4 \times 12$ 的网格，并打印两种方法找到的贪婪策略。这映照了表格 DP 常被检查的方式：价值显示奖励信息如何穿过网格传播，策略显示在规划后哪些动作是贪婪的。

策略改进和最终策略提取共享同一个辅助函数。先计算所有一步动作价值，然后把概率质量放在最大化动作上。如果多个动作并列，代码在它们之间均匀分配概率；这就是打印出的策略能在一个格子里显示多个箭头的原因。

```python
q_values = np.zeros((n_states, n_actions))
policy = np.zeros((n_states, n_actions))

for state in range(n_states):
    q_values[state] = one_step_lookahead(state, values, transitions, rewards, gamma)
    best_value = q_values[state].max()
    best_actions = np.flatnonzero(np.isclose(q_values[state], best_value))
    policy[state, best_actions] = 1.0 / len(best_actions)
```

完整的均匀扫描不是唯一的 DP 调度。异步版本就地更新状态，因此同一遍中后面的状态可能使用已经更新过的价值。只要每个状态更新得足够频繁，异步更新仍是动态规划。当某些状态比其他状态更重要时，它们变得有用，因为计算可以聚焦于状态空间中最相关的部分。我们在此不展开优先级扫描；只要知道完整均匀扫描不是贝尔曼更新唯一可能的调度就够了。

## 接下来是什么

动态规划假设转移和奖励模型已知。下一章去掉这个假设。当 $p$ 和 $r$ 未知时，价值函数必须从采样的片段和转移中估计：蒙特卡洛预测等待回报；时序差分预测一步一步地自举。
