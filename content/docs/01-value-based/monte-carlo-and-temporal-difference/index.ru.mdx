> **Аннотация.** Динамическое программирование оценивало политики, охватывая известную модель среды. Методы Монте-Карло и временных различий устраняют это предположение: агент оценивает значения на основе выборочного опыта. Мы остаемся на оценочной стороне истории: политика остается неизменной, пока мы узнаем, какую отдачу обычно приносят ее состояния.

Динамическое программирование является точным и понятным, но предполагает доступ к $p(s', r \mid s,a)$. Во многих задачах RL модель недоступна. Агент может действовать, наблюдать $S_t$, $A_t$, $R_{t+1}$ и $S_{t+1}$, но он не может перечислить все возможные следующие состояния или усреднить распределение переходов.

В этой главе задается более узкий вопрос: если политика $\pi$ фиксирована, как мы можем оценить ее функцию значения состояния $v_\pi(s)$ на основе выборочных эпизодов или переходов? Далее идут такие методы управления, как Sarsa и Q-Learning. Здесь мы делаем только **Прогноз model-free**.

## Оставляя динамическое программирование позади

Для фиксированной политики динамическое программирование использовало обновление ожиданий Беллмана:

$$
v_{k+1}(s) = \sum_a \pi(a \mid s) \sum_{s',r} p(s',r \mid s,a) \left[r + \gamma v_k(s')\right]
$$

Внутренняя сумма $\sum_{s',r} p(s',r \mid s,a)[r + \gamma v_k(s')]$ — это то место, где динамическое программирование использует самое сильное предположение. Чтобы его вычислить, агент должен знать полную одношаговую модель: какие следующие состояния могут последовать из $(s,a)$, какие награды могут появиться и насколько вероятна каждая пара $(s', r)$. В реальной задаче обучения эта информация обычно недоступна. Агент не имеет возможности проверять распределение переходов снаружи; ему остается только взаимодействовать с окружающей средой.

Прогноз model-free сохраняет идею Беллмана, но меняет способ доступа к ожиданию. Вместо явного усреднения по всем возможным следующим состояниям и вознаграждениям среда рассматривается как сэмплер. Агент выполняет действие, наблюдает одно вознаграждение и одно следующее состояние и использует этот единственный переход как свидетельство того, какое ожидание динамическое программирование могло бы вычислить на основе модели. Одна выборка является зашумленной, но многие выборки могут постепенно привести оценку стоимости к одному и тому же объекту: ожидаемому доходу при фиксированной политике.

Двумя основными методами прогнозирования model-free являются обучение методом Монте-Карло и обучение с использованием временных разностей; оба оценивают ценности на основе опыта, но используют разные части этого опыта в качестве цели обучения.

## Прогноз Монте-Карло

**Прогноз Монте-Карло** оценивает $v_\pi(s)$ путем усреднения доходности, наблюдаемой после посещения $s$. Здесь математическое ожидание — это функция ценности,

$$
v_\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s],
$$

и образцы представляют собой полные результаты, полученные в результате соблюдения политики $\pi$ в среде. Предположим, что эпизод посещает состояние $s$ в момент времени $t$. Доход от этого посещения представляет собой общее вознаграждение со скидкой, наблюдаемое после этого времени:

$$
G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots
$$

Этот $G_t$ является одним из образцов случайного дохода, ожидание которого определяет $v_\pi(s)$. Один эпизод дает зашумленный образец; многие эпизоды дают много таких образцов. Прогноз Монте-Карло сохраняет доходность, наблюдаемую после посещения каждого состояния, и использует среднее значение выборки в качестве оценки значения:

$$
V(s) = \frac{1}{N(s)} \sum_{i=1}^{N(s)} G^{(i)}(s)
$$

Важным моментом является то, что это обновление не использует вероятности перехода $p(s',r \mid s,a)$. Он не спрашивает, что могло случиться с $s$. Он ждет, чтобы увидеть, что на самом деле произошло после посещения $s$, а затем усредняет наблюдаемые результаты. В этом смысле предсказание MC — это model-free, но оно не онлайн в одношаговом смысле: обычный MC должен дождаться завершения эпизода, прежде чем станет известен возврат $G_t$.

Есть два стандартных варианта:

- **Первое посещение МК:** в каждом эпизоде обновляйте состояние только с момента его первого появления.
- Обновление **Каждое посещение МК:** при каждом появлении состояния в эпизоде.

Для MC при первом посещении каждый эпизод дает не более одной возвратной выборки на каждый состояние. Если состояние $s$ появляется несколько раз в одном и том же эпизоде, к среднему значению для $s$ добавляется только результат после первого появления. Вместо этого MC при каждом посещении использует все вхождения. Оба основаны на полной доходности; различие заключается только в том, какие посещения разрешены для предоставления образцов.

Процедура прогнозирования Монте-Карло при первом посещении выглядит следующим образом:

```
Input: policy pi to evaluate
Initialize V(s) arbitrarily for all states s
Initialize Returns(s) as an empty list for all states s

Repeat forever, or for a chosen number of episodes:
    Generate an episode following pi:
        S_0, A_0, R_1, S_1, A_1, R_2, ..., S_{T-1}, A_{T-1}, R_T

    G <- 0
    For t = T-1, T-2, ..., 0:
        G <- gamma * G + R_{t+1}
        If S_t does not appear in S_0, S_1, ..., S_{t-1}:
            Append G to Returns(S_t)
            V(S_t) <- average(Returns(S_t))
```

Поскольку MC использует фактическую выборочную доходность, а не полученную оценку будущего, MC при первом посещении дает несмещенную оценку на основе выборки в обычных эпизодических условиях. Его слабость — дисперсия: доход включает в себя все случайные вознаграждения с момента посещения до завершения, поэтому один необычный эпизод может отодвинуть оценку далеко от ее типичного значения. Эта высокая дисперсия — цена, которую платит MC за отказ от bootstrapping.

## Прогноз временной разницы

**Прогноз временной разницы** сохраняет настройку model-free Монте-Карло, но меняется при обновлении. Монте-Карло ждет конца эпизода, потому что ему нужен полный возврат $G_t$. TD(0), простейший метод временной разницы, обновляется, как только наблюдается следующее вознаграждение и следующее состояние.

Причина, по которой это возможно, заключается в том, что TD(0) использует одношаговую цель. После перехода $S_t, A_t, R_{t+1}, S_{t+1}$ наблюдаемое вознаграждение плюс текущая оценка значения следующего состояния рассматривается как новая оценка для $V(S_t)$:

$$
\text{TD target} = R_{t+1} + \gamma V(S_{t+1})
$$

Затем он перемещает старую оценку на небольшой шаг к этой цели:

$$
V(S_t) \leftarrow V(S_t) + \alpha \left[R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\right]
$$

В скобках указано количество **Ошибка ТД**:

$$
\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)
$$

Он измеряет расхождение между двумя прогнозами. До наблюдения перехода прогноз агента для состояния $S_t$ был $V(S_t)$. Увидев одну награду и приземлившись в $S_{t+1}$, он получил пересмотренный одношаговый прогноз: взять уже полученную награду, а затем добавить дисконтированную стоимость, присвоенную в данный момент следующему состоянию. Если этот пересмотренный прогноз больше, $V(S_t)$ движется вверх. Если он меньше, $V(S_t)$ перемещается вниз.

TD объединяет две уже знакомые идеи. Как и Monte Carlo, он учится по выборочному опыту и не требует динамики $p(s',r\mid s,a)$. Как и динамическое программирование, TD использует **bootstrapping**: цель содержит другую обучаемую оценку $V(S_{t+1})$, а не полный будущий return. Иными словами, одна оценка обучается по другой, но между ними находится одна реальная награда.

Для оценки политики табличная процедура TD(0) выглядит следующим образом:

```
Input: policy pi to evaluate
Parameter: step size alpha in (0, 1]
Initialize V(s) arbitrarily for all non-terminal states s
Set V(terminal) = 0

Repeat forever, or for a chosen number of episodes:
    Initialize S

    Repeat until S is terminal:
        Choose A according to pi(. | S)
        Take action A, observe R and S'
        V(S) <- V(S) + alpha [R + gamma V(S') - V(S)]
        S <- S'
```

Важным отличием от псевдокода Монте-Карло является положение обновления. TD(0) не ждет завершения эпизода, а затем движется назад по завершенной траектории. Он обновляется внутри эпизода сразу после каждого перехода. Это делает TD естественным для длительных эпизодов и продолжающихся задач, где окончательный возврат может задерживаться на длительное время или вообще отсутствовать.

Скорость обучения $\alpha$ контролирует, насколько сильно один переход меняет оценку. Маленький $\alpha$ медленно, но стабильно усредняет информацию; большой $\alpha$ заставляет функцию значения быстро реагировать на новый опыт за счет большего шума от отдельных переходов.

## Смещение и дисперсия

Монте-Карло и TD наиболее явно различаются по предвзятости и дисперсии.

Монте-Карло использует полный возврат $G_t$. Если выборка эпизодов осуществляется в соответствии с политикой $\pi$, результат является прямой выборкой того, что означает $v_\pi(s)$. Это дает MC низкую предвзятость, но высокую дисперсию: длинные эпизоды накапливают множество случайных событий, и все они влияют на обновление.

TD(0) использует одношаговую цель $R_{t+1} + \gamma V(S_{t+1})$. Обычно это имеет меньшую дисперсию, поскольку перед bootstrapping содержит только одну выборку вознаграждения. Но цель оказывается предвзятой всякий раз, когда $V(S_{t+1})$ ошибается. Часто так бывает на ранних этапах обучения.

Монте-Карло ждет дольше и использует более чистую цель. TD обновляется раньше и использует более зашумленную оценку будущего. Правильный выбор зависит от продолжительности эпизода, шума вознаграждения и того, насколько неточной является функция текущего значения.

Возможность TD обновляться онлайн является важным практическим преимуществом. Его можно обучать во время эпизода и естественным образом применять к продолжающимся задачам, когда ожидание завершения невозможно.

## Ступенчатый мост $n$

Монте-Карло и TD(0) являются конечными точками более крупного семейства. **$n$-шаговый возврат** ожидает выборки вознаграждений $n$, а затем загружается:

$$
G_t^{(n)} = R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1}R_{t+n} + \gamma^n V(S_{t+n})
$$

Когда $n=1$, это цель TD(0). Когда $n$ достигает конца эпизода, он становится возвращением Монте-Карло. Больший размер $n$ обычно означает меньшее смещение бутстрапа и большую дисперсию выборочного возврата. TD($\lambda$) и трассировки соответствия, которые мы здесь только просматриваем, объединяют множество целевых значений $n$ с экспоненциально убывающими весами.

## Эксперимент: Блэкджек

В запускаемом примере используется **Blackjack** — карточная среда для демонстрации Monte Carlo методов. Игрок стремится набрать сумму ближе к 21, чем у дилера, но не превысить 21. Карты с картинками стоят 10 очков. Туз называется **usable ace**, если его можно считать за 11 без перебора.

Это хороший пример прогнозирования model-free, поскольку агент не получает таблицу переходов. Он получает только эпизоды: последовательность видимых состояний, действий и наград из одной игры. Состояние, используемое в скрипте, представляет собой стандартное табличное наблюдение в блэкджеке:

$$
S_t = (\text{player sum}, \text{dealer showing}, \text{usable ace flag})
$$

Набор действий небольшой: `0` означает **палка**, а `1` означает **ударить**. Чтобы сохранить эту главу о прогнозировании, политика фиксирована, а не улучшена: игрок придерживается суммы 20 или 21, а в противном случае попадает. Задача состоит в том, чтобы оценить функцию стоимости этой политики,

$$
v_\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s],
$$

из многих образцов игр. Победа дает вознаграждение $+1$, проигрыш — $-1$, а ничья — $0$. Поскольку награды приходят только тогда, когда игра заканчивается, Блэкджек конкретизирует идею Монте-Карло: после посещения состояния возвращение — это просто конечный результат игры.

Полный сценарий реализует динамику блэкджека напрямую, вместо того, чтобы полагаться на библиотечную среду. Это делает задачу видимой: вытягивание карт, проверка на наличие полезного туза, применение фиксированной политики и создание одного эпизода — все это простые функции Python.

```python
def fixed_policy(state: State, stick_threshold: int = 20) -> int:
    """Stick on high sums and hit otherwise. 0 = stick, 1 = hit."""
    player_sum, _, _ = state
    return 0 if player_sum >= stick_threshold else 1
```

Генератор эпизодов возвращает переходы вида `(state, action, reward, next_state)`. Большинство удачных переходов имеют награду `0.0`, поскольку игра еще не закончилась. Если игрок вылетает, переход получает награду `-1.0`, и следующее состояние — терминальное. Если игрок придерживается позиции, дилер доигрывает оставшуюся часть игры, и последний переход получает `-1.0`, `0.0` или `1.0`.

```python
if action == 1:
    player.append(draw_card(rng))
    if is_bust(player):
        episode.append((state, action, -1.0, None))
        return episode
    next_state = observation(player, dealer)
    episode.append((state, action, 0.0, next_state))
    continue
```

Прогноз Монте-Карло при первом посещении ждет завершения эпизода, а затем возвращается к завершенной игре. Для каждого состояния используется только одна возвращаемая выборка из этого эпизода. Приведенное ниже обновление значения представляет собой постепенное выборочное среднее значение: вместо сохранения каждого возврата в списке оно напрямую обновляет текущее среднее значение.

```python
for state, _, reward, _ in reversed(episode):
    returns = reward + gamma * returns
    if state in values and state not in visited:
        counts[state] += 1
        values[state] += (returns - values[state]) / counts[state]
        visited.add(state)
```

TD(0) использует одни и те же эпизоды выборки, но обновляется после каждого перехода. Когда `next_state` является терминальным, следующее значение определяется как ноль. В противном случае цель загружается из текущей оценки следующего состояния Блэкджека.

```python
for state, _, reward, next_state in episode:
    next_value = 0.0 if next_state is None else values.get(next_state, 0.0)
    target = reward + gamma * next_value
    values[state] += alpha * (target - values[state])
```

Запуск на `200_000` эпизодах печатает несколько оценок и строит четыре поверхности ценности: для Monte Carlo и TD(0), отдельно с usable ace и без него. Точные числа зависят от seed, но знаки интерпретируемы. Состояние `(20, 10, False)` обычно хорошо при политике «stand на 20»: у игрока уже сильная рука, хотя дилер показывает 10. Состояние `(13, 2, False)` обычно плохо: политика требует hit, а многие следующие карты дают слабую руку или перебор.

Суть примера не в том, что эта политика оптимальна. Он не осуществляет контроль и не меняет своего поведения в зависимости от усвоенных значений. Цель состоит в том, чтобы продемонстрировать механизм прогнозирования на реальной эпизодической задаче: Монте-Карло ждет окончательного результата игры и усредняет полные доходы, в то время как TD(0) начинает перемещать значения, как только становятся доступны одно вознаграждение и одно следующее состояние.
